# lib/features/learn/widgets/study_calendar.dart

学习者答过题的那些天，作为学习标签页上的一张十二周格子图。

由记录推导而来、从不存储，和每日计数与单元进度条一样：某一天有记录在它上面被创建或最后一次复习，这一天就算作学习过。这比统计作答数要粗——同一天里对同一个词的第二次作答不会留下单独的痕迹——而这就是进度文件所记得内容的诚实边界。

消费方：`learn_page.dart`。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| `calendarWeeks` | 顶层常量 | B | 日历显示多少周——十二周，长到足以看出一个习惯、也看得出一处断档，短到能以清晰可读的方格尺寸放进一部手机。 |
| `StudyCalendar` | 类 | B | 学习者答过题的那些天，作为一张格子图。 |
| [`build`](#build) | 方法 | A | 构建这张格子图。 |
| `_cell` | 方法 | B | 画出一天；未来的一天画得很淡而不是留空，这样格子图直到这一周结束都保持它的形状。 |
| [`studiedDays`](#studieddays) | 顶层函数 | A | 找出在哪些本地日期上答过题。 |

## 文档

### `Widget build(BuildContext context, WidgetRef ref)` <a id="build"></a>

- **种类：** 方法
- **用途：** 构建这张格子图。
- **输入：** `context`、`ref`。
- **返回：** `Widget`；进度文件加载期间是一个空盒子。
- **副作用：** 除构建组件外无。
- **算法：** 读取学习过的那些天，找出 `calendarWeeks - 1` 周之前的那个星期一，然后每周排一列、每列七个 `_cell`，方格尺寸由可用宽度算出并夹在 6–18 逻辑像素（dp）之间。一行小结说明有多少天被填上了。
- **使用：** `learn_page.dart`。
- **说明：** 每周一列，最旧的在左边，今天在最后一列——因此学习者认得出的那个形状是右侧边缘。什么都没有的一天会被画出来，而不是跳过：那些空缺本身就是信息。

### `Set<String> studiedDays(ProgressData progress)` <a id="studieddays"></a>

- **种类：** 顶层函数
- **用途：** 找出在哪些本地日期上答过题。
- **输入：** 学习者的 `progress`。
- **返回：** `YYYY-MM-DD` 键的 `Set<String>`。
- **副作用：** 无。
- **算法：** 对每一条不是档案记录也不是历史记录的记录，取 `createdAt` 的本地日期，以及被设置时的 `lastReviewedAt` 的本地日期。
- **使用：** `build`，以及格子图下方的小结计数。
- **说明：** 一条记录的 `lastReviewedAt` 是它最后一次被作答的时间，而它的 `createdAt` 是它第一次被作答的时间，因为**记录由它的第一次作答创建**。两者都算，因此某人开始学一个词的那一天，即便之后又复习过它，仍会显示出来。档案记录被跳过：它由连续学习天数每天写入一次，会把什么都没学的日子也标上。句子历史记录出于同样的理由被跳过——查一个句子不算作答了什么，而一张凭它就填上的日历会夸大学习者做过的事。而一次**考试作答确实**算数：它的 `createdAt` 是它被记录下来的那一刻，也就是学习者做完一份卷子的那一刻——这是「某一天学习了什么」最清楚不过的情形。
