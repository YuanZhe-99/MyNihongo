# lib/features/sentence/services/lexicon.dart

内置目录上的"表层 → 词条"索引。`ContentCatalog` 按 id 查找词条，这正是参考页面所需要的；而阅读日语文本需要的是反方向——给定一串字符，它可能是哪些词条。

目前它服务于发音评分：答以汉字的识别器必须先被改写成假名，对照才有意义。`PLAN.md` M2.3 的句子分析器会扩展这同一个类，而不是另建一份索引——这也是它已经位于 `features/sentence/` 之下的原因。

使用方：`pronunciation_practice_sheet.dart`（目录加载后构建一个）、`pronunciation_scorer.dart`（使用它）。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| `Lexicon` | 类 | B | 目录上的"表层 → 词条"索引。 |
| `build` | 静态方法 | B | 从内置目录构建索引。 |
| `entryCount` | getter | B | 索引覆盖多少词条，用于诊断和测试。 |
| `byHeadword` | 方法 | B | 查找正是这样书写的词条。 |
| `byReading` | 方法 | B | 查找这样读的词条，两种字体皆可。 |
| [`toKana`](#tokana) | 方法 | A | 把文本改写为假名，经由目录解析汉字。 |

## 文档

### `String toKana(String text)` <a id="tokana"></a>

- **种类：** 方法
- **用途：** 把识别器的答案变成能与假名读音对照的东西。
- **输入：** `text`——通常是语音识别器返回的内容。
- **返回：** 同一段文本，其中每个被识别出的词头都换成了它的读音。仍需规范化，见说明。
- **副作用：** 无。
- **算法：** 从左侧开始贪心最长匹配，上限为目录中最长的词头。
- **使用：** `PronunciationScorer._resolve`。
- **说明：** 当词条写作汉字时识别器也会答汉字，把它与假名读音逐字对照会把一次完美的朗读判成零分。目录不认识的片段会**原样**透传，因此未能解析的汉字仍会消耗编辑而不是凭空消失——分数对"读不出来的部分"保持诚实。规范化留给调用方，并对整个结果一次性施加，因为长音符的元音取自它前面的音拍，在循环内部规范化会把它丢掉。
