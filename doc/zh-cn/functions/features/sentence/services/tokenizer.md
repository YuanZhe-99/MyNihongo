# lib/features/sentence/services/tokenizer.dart

用词格和最短路径把日语文本切分成词元。日语没有空格，因此分词是一次搜索：分词器在每个位置提出它能给出的所有读法，为每一种定价，然后取整句最便宜的路径。

代价表及每个数字背后的理由推导见 [../../../../algorithms/sentence-analysis.md](../../../../algorithms/sentence-analysis.md)；本页记录各项声明。

使用方：`sentence_analyzer.dart`。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| `_Edge` | 类 | B | 一段跨度的一种候选读法，带词元、终点与代价。 |
| `_Edge.start` | getter | B | 边的起点——并不总是它被提出的位置。 |
| `Tokenizer` | 类 | B | 把文本切分成词元。 |
| [`tokenize`](#tokenize) | 方法 | A | 用最短路径把文本切分成词元。 |
| `normalize` | 静态方法 | B | 只做宽度规范化，不触碰假名与汉字。 |
| [`_edgesAt`](#edgesat) | 方法 | A | 提出从某个位置开始的所有读法。 |
| `_entryPenalty` | 静态方法 | B | 结合上下文为一个目录候选定价。 |
| [`_stemEdges`](#stemedges) | 方法 | A | 把助动词连同它前面的词干一起提出。 |
| `_stemForm` | 静态方法 | B | 把词干形态命名为形式，写入词元的形式链。 |
| `_functionWordToken` | 静态方法 | B | 为功能词构建词元。 |
| `_runEnd` | 静态方法 | B | 找出某类字符连续段延伸到哪里。 |
| `_isNumeral`、`_isKatakana`、`_isKana`、`_isPunctuation` | 静态方法 | B | 字符类别。 |

## 文档

### `List<Token> tokenize(String text)` <a id="tokenize"></a>

- **种类：** 方法
- **用途：** 把句子变成词。
- **输入：** 学习者输入的 `text`。
- **返回：** 按顺序排列的词元，偏移量指向规范化后的文本。
- **副作用：** 无。
- **算法：** 在各位置上做动态规划：`best[i]` 是到达 `i` 的最便宜方式，每条边从**它自己的起点**松弛。随后回溯路径并反转。
- **使用：** `SentenceAnalyzer.analyze`。
- **说明：** 从边自身的起点而不是从提出它的位置松弛是关键：词干边在助动词处被提出，却覆盖它前面的词干，弄错这一点正是本流程的第一个 bug——一个敬体过去动词被解析成未知的词干加上无人解释的助动词。

### `List<_Edge> _edgesAt(String input, int i, _Edge? incoming)` <a id="edgesat"></a>

- **种类：** 方法
- **用途：** 枚举某个位置上的候选读法。
- **输入：** 规范化后的 `input`、位置，以及到达该位置的边。
- **返回：** 从该位置开始或覆盖该位置的所有边。
- **副作用：** 无。
- **算法：** 在词典最大键长内由长到短：功能词、目录词、词干边。随后是数字串、片假名串、标点、裸连用形词干，以及始终提出的单字符未知边，使路径总能到达句尾。
- **使用：** `tokenize`。
- **说明：** `incoming` 只用于给量词定价：紧跟数字的量词打折，没有数字的量词加价，因为同时是名词和量词的词在没有数字说明时就是名词。

### `List<_Edge> _stemEdges(String input, int start, int end, FunctionWord word, String surface)` <a id="stemedges"></a>

- **种类：** 方法
- **用途：** 把一个活用的动词或形容词作为一条边提出。
- **输入：** 输入、助动词的跨度、助动词本身及其表层。
- **返回：** 词干可能来自的每个词各一条边。
- **副作用：** 无。
- **算法：** 从助动词往前尝试每种词干长度；询问还原器：在助动词所要求的形态下，哪些目录词条可能产生该词干。
- **使用：** `_edgesAt`，只要功能词声明了词干形态。
- **说明：** **活用还原正是在这里进入搜索的。** 助动词永远只与它能附着的真实词一起被提出，因此名词后面的敬体词尾绝不会被采用，活用动词到达时已是两个知道词典形的词元。边从词干开始，这才让最短路径能把整个动词与其他方案放在一起权衡。
