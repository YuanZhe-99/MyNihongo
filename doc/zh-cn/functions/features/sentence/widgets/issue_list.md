# lib/features/sentence/widgets/issue_list.dart

各项检查提出的可能问题：句子实验室的最后一节。

使用方：`sentence_lab_page.dart`。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| `IssueList` | 类 | B | 各条结论，每条引用它所针对的句子片段。 |
| `IssueList.onExplain` | 字段 | B | 以问题下标与**本 widget 为它显示的那句说明**回调；为 null 时隐藏按钮。 |
| `IssueList.cardBuilder` | 字段 | B | 在某条问题下构建生成卡片（如果有）。 |
| `build` | 方法 | B | 构建问题列表，或"没有看到异常之处"那一行。 |
| `_span` | 方法 | B | 引用一条问题所针对的句子片段。 |
| [`_message`](#message) | 方法 | A | 为一条问题措辞。 |

## 文档

### `String _message(AppLocalizations l10n, Issue issue)` <a id="message"></a>

- **种类：** 方法
- **用途：** 把一条结论变成学习者可以据以行动的话。
- **输入：** 本地化与该条问题。
- **返回：** 一句话。
- **副作用：** 无。
- **算法：** 按类型分支，助词框架一项根据能否指名替换词在两种措辞间选择。
- **使用：** `build`。
- **说明：** 每条消息都以"可能"的语气措辞，因为分析器没有关于作者意图的模型。助词框架有两种措辞是刻意的：当自他动词对表知道对应词时指名替换动词很有用，而在它不知道时凭空编一个建议会比不给更糟。

### 可选的「解释」按钮 <a id="explain"></a>

凡是端侧 AI 关闭或不可用之处，`onExplain` 都是 null，正是这个 null 移除了按钮——这个 widget 对该功能没有别的认知。设置了它时，回调拿到的是**本 widget 渲染出的那句说明**，而不只是 `Issue`。这是刻意的：提示词必须就学习者正在读的那句话发问，而在上游另行推导一句措辞不同的问题，会把答案放在一个不在屏幕上的问题之下。

`cardBuilder` 返回生成卡片，它渲染在确定性行**之下**，而不是旁边或取而代之。结论才是答案，生成的文字只是对它的评论。
