# lib/features/drills/views/exam_history_page.dart

学习者做过的每一份 JLPT 卷子，最新的在前，并带上他们答错的那些题。

一个位于标签页外壳之外的全屏路由，理由和测验与句子实验室一样：它是带着目的从学习标签页进入、做完就离开的东西，而不是一个可供浏览的地方。

页面读取 `examAttemptsProvider`，因此在这里写下的、从备份还原的，或从另一台设备同步进来的作答，都以同样的方式抵达这个列表。只保存了作答，所以题目文字、它的选项和它的解析都是在某个条目卡片被展开的那一刻从随包发布的真题练习文件里读回来的。

消费方：`/exam-history` 路由，从 `JlptPracticeCard` 的结果按钮进入。

## 文档

### `Widget build(BuildContext context, WidgetRef ref)` <a id="build"></a>

- **种类：** `ExamHistoryPage` 的方法
- **用途：** 构建作答列表，或说明一次也没有。
- **输入：** `context`、`ref`。
- **返回：** 当前状态对应的组件树。
- **副作用：** 根据当前状态创建 UI 组件。
- **算法：** 监听 `examAttemptsProvider`。里面什么都没有时，居中显示空状态那一行；否则是一个 `ListView.builder`，它的第一行是那条固定的说明，其余各行每行一个 `_AttemptTile`，整体放在 `pageMaxContentWidth` 约束内。
- **使用：** `/exam-history` 路由。
- **说明：** 保持这个方法开销小，因为 Flutter 可能会频繁调用它。顶部那条说明不是装饰：一个在 JLPT 几个字母旁边显示「67 题中的 48 题」的屏幕，除非它自己说明，否则会被读成一个 JLPT 成绩。进度文件还在加载时学习者看到的也是一个空列表，这是刻意的——屏幕上没有任何东西需要把「尚未加载」和「还什么都没有」区分开来。

### `Widget build(BuildContext context, WidgetRef ref)` —— `_AttemptTile` <a id="tile"></a>

- **种类：** `_AttemptTile` 的方法
- **用途：** 构建一次作答的概要及其详情。
- **输入：** `context`、`ref`；`attempt` 字段。
- **返回：** 当前状态对应的组件树。
- **副作用：** 根据当前状态创建 UI 组件；使用删除动作时删除该记录。
- **算法：** 一个 `Card` 里的 `ExpansionTile`：标题是级别与模式，副标题是本地的开始时间、整卷的得分，以及每一个被 `DrillSection.parse` 认出的部分的得分标签。展开后显示 `_WrongQuestions`，以及一个调用 `NihongoStorage.deleteRecords` 并重新加载 `progressDataProvider` 的删除动作。
- **使用：** `ExamHistoryPage.build`，每次作答一次。
- **说明：** 保持这个方法开销小，因为 Flutter 可能会频繁调用它。答错的题只在条目卡片被展开时才加载，因为显示它们意味着读取多达四个内容文件，而长列表里的大多数作答从来不会被打开。删除是**真删除，不是墓碑**：三方合并把「一侧删除、另一侧未改动」的记录视为已删除，因此在这里移除的一次作答会在下一次同步时在各处被移除——一条又回来的记录，会比根本没有删除按钮更糟。本构建没有对应 `DrillSection` 的部分键会被跳过，而不是不带名字地显示出来。

### `Widget build(BuildContext context, WidgetRef ref)` —— `_WrongQuestions` <a id="wrong"></a>

- **种类：** `_WrongQuestions` 的方法
- **用途：** 显示错在哪里，从随包发布的文件里连回来。
- **输入：** `context`、`ref`；`attempt` 字段。
- **返回：** 当前状态对应的组件树；级别解析不出来、文件尚未加载，或什么都没做错时，返回一个空盒子。
- **副作用：** 通过 `drillLevelProvider` 读取真题练习资源。
- **算法：** 解析这次作答的级别，监听该级别的真题练习文件，把其中每一道题按 id 建索引，然后取出那些不为 1 的作答，按题目 id 排序。每一条渲染它的答错／未作答标签、题目的日语（带读音，除非该题型会隐藏它）或它的提示语、正确的选项，以及有解析时的解析。
- **使用：** `_AttemptTile.build`，作为展开后的子组件。
- **说明：** 保持这个方法开销小，因为 Flutter 可能会频繁调用它。只保存了作答，所以题目文字、它的选项和它的解析现在全都从内容文件里读取。这正是只保存输入的意义所在：一次修正了答案键的内容更新会连同历史记录一起修正，而不是留下一份应用已经不再认同的冻结副本。随包发布的文件里已经没有的题目会用一行说明——内容在各个版本之间会被重写，而一次悄悄丢掉三行的作答，会是比一次承认这一点的作答更糟的记录。文件加载期间什么也不显示，而不是显示一个转圈的指示：`ExpansionTile` 在它的子组件被显示出来之前就会构建它们，所以这里的一个转圈指示会在列表里每一个折叠着的行背后——不可见地——转起来，而这段等待不过是读四个小文件的几毫秒。
