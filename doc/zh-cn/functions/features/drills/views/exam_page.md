# lib/features/drills/views/exam_page.dart

计时 JLPT 卷子的一次作答：画出一份卷子或接着做保存的那一份，让每个计时部分按各自的计时运行，记录这次作答，并清掉保存。

它和测验一样，是标签页外壳之外的一个全屏路由：进来是带着目的的，做完了才离开，而一个走着计时的界面下方还摆着导航栏，等于是在邀请人离开。

页面拥有 [`ExamSession`](../services/exam_session.md) 刻意不做的一切：读取练习题文件、画出卷子、写下保存，以及把一份做完的卷子变成一条 `exam:` 记录。它是一个 `WidgetsBindingObserver`，因为应用离开前台时计时必须停下，而回来时必须重新检查截止时刻。

使用方：`/exam` 路由，由 `JlptPracticeCard` 带着一个 `ExamConfig` 进入。

## 文档

### `void didChangeAppLifecycleState(AppLifecycleState state)` <a id="lifecycle"></a>

- **种类：** 方法
- **用途：** 应用离开前台时停止计时，回来时再接着走。
- **输入：** 新的 `state`。
- **返回：** 无。
- **副作用：** 暂停或继续计时；保存；可能交上当前计时部分。
- **算法：** 没有 session、或者卷子已经记录之后，什么也不做。在 `resumed` 上先 `checkDeadline()`，只有它没有触发时才继续计时；其他状态则暂停计时并保存。
- **使用：** Flutter 框架，通过 `WidgetsBindingObserver`。
- **说明：** 计时衡量的是投入的注意力，不是墙上的钟点。一个去接电话的学习者并没有把那段时间花在卷子上，而一个把它放了一整夜的学习者也没有丢掉这份卷子。回来的路上会重新检查截止时刻，因为一部睡过了截止时刻的手机必须在醒来时发现这件事，而不是继续做一个几小时前就结束了的计时部分。

### `Future<void> _build()` <a id="build-paper"></a>

- **种类：** 方法
- **用途：** 画出卷子，或接着做保存的那一份。
- **输入：** 无；读取配置、JLPT 结构和该级别的练习题文件。
- **返回：** 无。
- **副作用：** 读取资源与保存文件；构建一个 `ExamSession` 并挂上监听者。
- **算法：** 等待结构，接着做时还要等待保存；在保存里有的地方，从保存取用级别与 scale。等待该级别的练习题文件，按 id 为每道题建索引，并把每个 id 映射到它所属的部分。然后要么重建保存的那些计时部分——逐个查找题目 id，丢掉已经不在的那些，再 `restore` 每个计时部分的答案——要么画出新的：对规格里的每个计时部分，保留可以作答的那些部分，对每一个按题目构成与已经问过的 id 做 `DrillSampler.drawByPassage`，并跳过最后一道题都没有的计时部分。收集所选题目引用到的文章，然后设置 session。
- **使用：** 来自 `initState` 的帧后回调。
- **说明：** 仅在本文件内部使用的辅助函数。

  **没有日语语音时听力会被丢掉**，而且这个计时部分是被整个排除在卷子之外，而不是显示出来再跳过：一个谁也听不见的计时部分，不是一个有人考了零分的部分。

  随包发布的文件里已经没有的题目 id 会在接着做时被丢掉。内容在各个版本之间会被重写，而一份因为三道题被重新编号就拒绝继续的卷子，会比一份少三道题、并说明自己一共问了多少题的卷子更糟。

  接着做时没有可读的保存，或者某个级别没有规格，都会让 `_exam` 保持为 null，页面会说没有内容，而不是显示一份空卷子。

### `QuizSession _sessionFor(List<DrillQuestion> questions, Locale locale)` <a id="sessionfor"></a>

- **种类：** 方法
- **用途：** 构建一个计时部分的 session。
- **输入：** `questions` 与 `locale`。
- **返回：** `QuizSession`。
- **副作用：** 无；它返回的 session 通过 `progressDataProvider` 记录作答。
- **算法：** 按 locale 转换每一道练习题，并用 `requeue: false` 和一个调用 `recordAnswer` 的 `onFirstAnswer` 构造一个 `QuizSession`。
- **使用：** `_build`，每个计时部分一次。
- **说明：** 仅在本文件内部使用的辅助函数。**不重新排队：** 在学习者答错之后再问一遍，是练习教人的方式，也恰恰是考试绝不能做的事——一份长度取决于做得好不好的模拟考试，没法按固定的题目构成来判分。每一次作答仍然会推动对应学习项的复习间隔：坐下来做一份模拟考试就是在学习，调度不该假装这件事没有发生。

### `void _onExamChanged()` <a id="onexamchanged"></a>

- **种类：** 方法
- **用途：** 跟着考试的计时走，并在每次变化后保存。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 重建；写入保存文件。
- **算法：** `setState` 加上一个不等待的 `_save()`，并以 `mounted` 为守卫。
- **使用：** 在 `_build` 里作为监听者挂到 session 上。
- **说明：** 仅在本文件内部使用的辅助函数。在每次通知时保存，也就是一个计时部分进行期间每秒一次，那是对一个别的东西都不会读的文件做一次小的原子写入——而另一种选择，是一份卷子被一部没电的手机弄丢。

### `Future<void> _save()` <a id="save"></a>

- **种类：** 方法
- **用途：** 把卷子写下来，或者在它做完之后清掉。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 写入或删除保存文件；刷新 `savedExamProvider`。
- **算法：** 没有 session 时返回。做完的卷子清掉保存；其他情况写入 `exam.toJson()`。然后刷新 `savedExamProvider`。
- **使用：** `_onExamChanged`、生命周期回调，以及 `_confirmLeave`。
- **说明：** 仅在本文件内部使用的辅助函数。这次刷新是对一个真实 bug 的修复：Learn 卡片通过一个 `FutureProvider` 读取保存，而它在这份卷子存在之前就已经解析完了。没有它，学习者离开一份做了一半的考试，本该提出继续的那张卡片却什么也不显示——在加上那一行之前，设备上就是这样。

### `Future<void> _record()` <a id="record"></a>

- **种类：** 方法
- **用途：** 记录做完的卷子并清掉保存。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 通过 `progressDataProvider` 写入一条 `exam:` 记录；删除保存文件；刷新 `savedExamProvider`。
- **算法：** 以 `_finished` 为守卫并先把它设上。走遍每一个计时部分：把这个计时部分的用时与限时记在它第一个部分的名字下，并把每一条结果计入该部分的问过／答对计数，把答案存为 1、0 或 `examUnanswered`。什么都没作答时不写入即返回。用已作答的键的哈希给 id 加盐，然后 `recordExam` 一个带着各部分 `ExamSectionResult` 的 `ExamAttempt`，并清掉保存。
- **使用：** 结果视图上的完成按钮。
- **说明：** 仅在本文件内部使用的辅助函数。**只写一次，在最后**，因为半份卷子不算一次作答——而且与一次分项练习不同，被放弃的模拟考试根本不会被记录。未作答是作为它自己的取值存下来的，而不是作为答错，所以正确率是相对于实际尝试过的题目而言的。用时读自 `usedBefore`，到那时它已经是精确的，因为交上一个计时部分会先暂停它的计时。

### `Future<bool> _confirmLeave()` <a id="confirmleave"></a>

- **种类：** 方法
- **用途：** 离开一份还在进行的卷子前先确认。
- **输入：** 无。
- **返回：** `Future<bool>`——是否弹出。
- **副作用：** 暂停计时并保存；可能显示一个对话框。
- **算法：** 没有 session、卷子已经记录、或者每个计时部分都已交上时，直接放行。否则暂停、保存并询问；学习者选择留下时继续计时。
- **使用：** `build` 里的 `PopScope`。
- **说明：** 仅在本文件内部使用的辅助函数。与测验不同，这里的答案不是「剩下的会被丢弃」：卷子被保存下来，Learn 卡片会提出继续做它。所以这是一个告知性的对话框，而不是一个警告，而且它会说明卷子去了哪里。计时是在对话框*之前*暂停的，所以读它花掉的那几秒不会从这个计时部分里扣掉。

### `Widget build(BuildContext context)` <a id="build"></a>

- **种类：** 方法
- **用途：** 构建开始卡片、计时部分，或者结果。
- **输入：** `context`。
- **返回：** 当前状态对应的组件树。
- **副作用：** 根据当前状态创建 UI 组件。
- **算法：** 一个 `canPop: false` 的 `PopScope`，只在 `_confirmLeave` 同意后才弹出，里面包着一个脚手架，其 body 依 `(_building, exam)` 分支：构建期间是一个转圈指示，session 为 null 时是没有内容那一行，每个计时部分都交上之后是 `ExamResultsView`，两个计时部分之间是开始卡片，其余情况则是正在进行的那个计时部分——全都放在一个 `pageMaxContentWidth` 约束之内。
- **使用：** `/exam` 路由。
- **说明：** 保持这个方法开销小，因为 Flutter 可能会频繁调用它。结果视图上的完成按钮会在弹出之前调用 `_record`，正是它让这次作答得以存在；navigator 是在 await 之前捕获的，而不是跨着它去取。

### `Widget _block(AppLocalizations l10n, ExamSession exam)` <a id="block"></a>

- **种类：** 方法
- **用途：** 运行正在计时的那个计时部分。
- **输入：** `l10n`、`exam`。
- **返回：** `Widget`。
- **副作用：** 无；它返回的运行器驱动这个计时部分的 session。
- **算法：** 一个按计时部分索引加 key 的 `QuizRunner`，跑在这个计时部分的 session 之上，`showFeedback: false`，以 `_passageFor` 作为它的前导构建器，一个带着各部分名称与等宽数字 `mm:ss` 倒计时的头部，并以 `finishBlockEarly` 作为它的 `onFinished`。
- **使用：** `build`，在一个计时部分进行期间。
- **说明：** 仅在本文件内部使用的辅助函数。**题与题之间没有反馈：** 一份卷子是在最后判分的，而每答一道就被告知结果，正是真考试最明显不会做的事。值得上色的是最后一分钟——在那之前红色的倒计时只是噪音，在那之后也已经没什么可警告的了。等宽数字让倒计时不会随着数位变化而抖动。
