# lib/features/drills/widgets/listening_script_player.dart

逐行播放一段听力脚本，并在听力原文不再等同于答案之前把它藏起来。

听力原文正是让聴解练习有价值的东西——学习者必须能看到自己漏掉了什么——而它同时也是会让题目变得白送的东西。所以它在题目作答之后才出现，绝不提前。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| [`ListeningScriptPlayer`](#player) | 类 | A | 在播放次数上限之下播放一段脚本，听力原文受门控。 |
| `_ListeningScriptPlayerState` | 类 | B | 保存播放次数、是否正在播放，以及当前高亮的是哪一行。 |
| `dispose` | 方法 | B | 停下引擎，免得一段没播完的脚本盖过接下来的内容。 |
| [`_play`](#play) | 方法 | A | 把脚本朗读出来，一次一行。 |
| [`build`](#build) | 方法 | A | 构建播放控件，以及作答之后的听力原文。 |

## 文档

### `class ListeningScriptPlayer` <a id="player"></a>

- **种类：** 类
- **用途：** 播放一段听力脚本。
- **输入：** `passage`；`maxPlays`——它最多可以被听几遍；`revealed`——听力原文是否可以显示。
- **返回：** 一个组件（widget）。
- **副作用：** 播放之前没有。
- **算法：** 一个播放按钮，旁边是剩余播放次数，`revealed` 之后下方是听力原文。
- **使用：** `quiz_page.dart` 的 `_passageFor`，作为听力题在运行器中的前置组件。
- **说明：** `maxPlays` 在练习中不设上限，在模拟考试中为一，因为真正的聴解每道题只播一遍，按另一套规则练习会养成考试要惩罚的习惯。`revealed` 跟随本次会话的结果，所以在题目还没作答时听力原文绝不会出现在屏幕上。

### `Future<void> _play()` <a id="play"></a>

- **种类：** 方法
- **用途：** 把脚本朗读出来，一次一行。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 产生音频；每一行被读到时高亮它。
- **算法：** 已在播放、没有日语语音，或已达播放次数上限时拒绝执行；否则依次走过各行，点亮每一行并等待它读完再开始下一行。
- **使用：** 播放按钮。
- **说明：** 仅在本文件内部使用的辅助函数。每一行都要等它读完才开始下一行，这才让高亮有意义。每一行之前都先调用 `stop()`，因为 `TtsService.speak` 会把重复朗读它正在读的同一段文本当作停止请求——否则有两行完全相同的脚本会在第二行上变哑。内容里写了读音的地方就按读音朗读：引擎拿到 一日 只能在 ついたち 和 いちにち 之间猜，而音频猜错了的听力题是没法作答的。

### `Widget build(BuildContext context)` <a id="build"></a>

- **种类：** 方法
- **用途：** 构建播放控件，以及作答之后的听力原文。
- **输入：** `context`。
- **返回：** 当前状态对应的组件树。
- **副作用：** 根据当前状态创建 UI 组件。
- **算法：** 按钮；有上限时显示剩余次数标签；没有语音时显示原因；并且——仅在 `revealed` 时——显示听力原文，并高亮当前正在朗读的那一行。
- **使用：** Flutter，在每次重建时。
- **说明：** 保持这个方法开销小，因为 Flutter 可能会频繁调用它。没有日语语音时，控件是**禁用而不是隐藏**，原因就写在旁边：一道看不到任何收听方式的听力题看起来像个 bug，这与 `SpeakButton` 遵循的规则相同。
