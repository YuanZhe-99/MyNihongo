# lib/features/drills/models/drill_section.dart

为 JLPT 卷子的四个部分，以及每个部分由哪些题型构成命名。只有两个枚举和它们的解析器，别无他物。

**这些名字是兼容性契约。** 部分名会写进每一条考试记录的载荷，题型键会写进每一个练习题文件，因此重命名其中一个会悄悄让已经使用它的记录和内容变成孤儿。每种题型的*数量*刻意不在这里——它们在 `structure.json` 里，因为 JEES 说这些数量每次考试都会变，而会变的数字属于内容而不属于代码。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| 库头 | 库文档 | B | 为 JLPT 卷子的四个部分，以及每个部分由哪些题型构成命名。 |
| [`DrillSection`](#section) | 枚举 | A | 四个部分：文字・語彙、文法、読解、聴解。 |
| `DrillSection.parse` | 静态方法 | B | 从内容 JSON 或保存的记录里解析出部分；无法识别时为 null。 |
| [`DrillType`](#type) | 枚举 | A | 一个大問——卷子上编了号的一种题型。 |
| `DrillType` 构造函数 | 构造函数 | B | 把题型绑定到它的内容键和它所属的部分。 |
| `key`、`section` | 字段 | B | 练习题文件在 `type` 里写什么，以及该题型计分时归入哪个部分。 |
| `DrillType.parse` | 静态方法 | B | 从练习题文件里解析出题型；无法识别时为 null。 |
| `DrillTypeName` | 扩展 | B | 大问在卷子上印出来的名称。 |
| `jaName` | getter | B | 用日语说出一个大问的名称，对 `DrillType` 穷尽。 |

## 文档

### `enum DrillSection` <a id="section"></a>

- **种类：** 枚举
- **用途：** 为卷子的一个部分命名。
- **输入：** 无；只有内容文件会写出这些名字，没有别的东西构造它们。
- **返回：** 无。
- **副作用：** 无。
- **算法：** 无。
- **使用：** `DrillFile`、`DrillRepository.assetFor`、`DrillSampler`、Learn 卡片，以及每一条考试记录的载荷。
- **说明：** JLPT 把它们称作 文字・語彙、文法、読解 和 聴解。即使某个级别把其中两个放在同一个计时部分里考，这里也把它们分开，因为计分组是由部分组成的，薄弱点报告也是按部分来读的。`parse` 折叠大小写，所以写成 `Vocab` 的文件照样能加载；它返回 null 而不是某个默认值：不属于任何部分的题目无法计分，悄悄把它归到文字・词汇下会把它放进错误的组里。

### `enum DrillType` <a id="type"></a>

- **种类：** 枚举
- **用途：** 为一个大問命名，并把它绑定到计分所归属的部分。
- **输入：** 内容写出的 `key`；计分所归属的 `section`。
- **返回：** 无。
- **副作用：** 无。
- **算法：** 无。
- **使用：** `DrillQuestion.type`、`DrillTypeRendering`、`LevelStructure.types`、`DrillSampler.draw`。
- **说明：** 键是练习题文件写出的东西，部分是该题型计分时归入的地方。两个级别可以共用一种题型而给它不同的数量，这正是数量住在 `structure.json` 里、而这里只保留*形状*的原因。键采用 kebab-case 而不是 Dart 的名字，因为内容文件是手写的，连字符在那里比驼峰更好读。`parse` 返回 null 而不是某个默认值——内容门禁会在未知题型出货前就拒绝它，这里是第二道防线：丢掉这道题，好过把它记到一个它并不属于的部分名下。

`jaName` 扩展给每个大问它官方的日语标题——漢字読み、文脈規定、即時応答——而不是翻译过的名称，并且刻
意不放进 ARB 词条里。这些是 jlpt.jp 印的标题，所以学习者拿薄弱点页面和真卷子对照时看到的是同一批
字；标签里本地化的那一半是旁边显示的部分名称，那部分 ARB 确实有。
