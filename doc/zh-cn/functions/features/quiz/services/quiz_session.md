# lib/features/quiz/services/quiz_session.dart

把一次测验从第一题运行到总结：队列、判分、重排与计分。

写入进度是一个**回调**而不是依赖，因此该文件不 import 任何存储，测试也能精确观察它本会写入什么。

有三个 getter 是为计时的模拟考试而存在的，它们建立在一对练习测验从不读取的 `_answers` / `_all` 字段之上。`_answers` 按 `scoreKey` 保存每道题的**第一次**作答——也就是计了分的那一次——而 `chosen` 把它公开出来：一份保存的考试是按当时选了什么写下的，而不是按它当时得到的判定，所以通过 [`restore`](#restore) 重放它时，会按内容文件现在的样子重新判分。`_all` 是这次会话构建时带的每一道题，包括 `append` 加进来的任何一道，而 `allQuestions` 把它公开出来，因为结果屏幕需要题目本身——结果只说明哪些做错了，却没说它们是什么，而为了弄清楚再去读一遍内容文件，等于重新回答一个会话已经知道答案的问题。`remainingKeys` 是一份保存的另一半：仍未问到的那些题目，按顺序排列，与 `outcomes` 所说已经作答的那些并列。

## 文档

### `class QuestionOutcome` <a id="questionoutcome"></a>

- **种类：** 类
- **用途：** 报告一道题目的首次结果。
- **输入：** `key`——该题的计分键；`itemId`；`correct`；`answered`。
- **返回：** 一个不可变值。
- **副作用：** 无。
- **算法：** 无。
- **使用：** `outcomes`，考试记录由它构建。
- **说明：** 每道题一条而不是每次尝试一条，并且是每道**题目**一条而不是每个条目一条：一份卷子会用四种不同方式问 会う，而把它们并成一行的结果页会藏掉其中三个。`answered: false` 是计时部分时间到了之后留下的东西——它不是答错，没有人答错，考试记录把它存成自己的一个取值，这样正确率就是在实际尝试过的题目上算的。

### `class QuizSession` <a id="session"></a>

- **种类：** 类
- **用途：** 在一个固定的题目列表上运行一次测验。
- **输入：** `questions`；`onFirstAnswer`，每个条目调用一次，告知**首次**作答是否正确；`requeue`。
- **返回：** 一个供页面监听的 `ChangeNotifier`。
- **副作用：** 作答之前没有；它自己不持有任何存储。
- **算法：** 一个以当前题目为队首的队列、一张以 `scoreKey` 为键的首次结果表、每个键的重排次数，以及一个有序的 `QuestionOutcome` 列表。
- **使用：** `quiz_page.dart` 构建一个并交给 `QuizRunner`。
- **说明：** `onFirstAnswer` 按每次作答触发而不是结束时统一触发，因此中途被杀掉的应用仍保留已答的部分。`requeue` 对计时的卷子是关闭的：学习者答错之后再问一遍是练习教人的方式，同时也恰恰是考试绝不能做的事——一场长度取决于做得好不好的模拟考试，没法按固定的题目构成来计分，而计时器也会在给每个学习者量一份不同的卷子。

### `static String scoreKey(QuizQuestion question)` <a id="scorekey"></a>

- **种类：** 静态方法
- **用途：** 给出一道题目计分所用的键。
- **输入：** `question`。
- **返回：** `String`——有 `questionId` 时用它，否则用 `itemId`。
- **副作用：** 无。
- **算法：** 一个空值合并表达式。
- **使用：** `answer`、`next`、`forfeit`、`restore`，以及保存的模拟考试格式。
- **说明：** 练习题有自己的 id，因为一份卷子会围绕同一个词问好几道不同的题，把它们按一个条目计分意味着第二道和第三道永远不会被计入。其余的一切都按条目计分，一直如此：关于同一个语法点的两道生成的题，就是同一道题问了两遍。

### `QuizOutcome answer(QuizAnswer answer, {bool? acceptedAnyway})` <a id="answer"></a>

- **种类：** 方法
- **用途：** 判当前题目并保留结果。
- **输入：** 学习者做了什么；`acceptedAnyway`，即端侧模型的第二意见。
- **返回：** `QuizOutcome`，同时保留为 `lastOutcome`。
- **副作用：** 可能调用 `onFirstAnswer`；向 `outcomes` 追加一条；通知监听者。
- **算法：** 判分；若这是其计分键下的首次作答，就记录结果、追加一条 `QuestionOutcome`、答错时把条目写进错题名单，并在题目不是生成的且该条目尚未被记录时回调；保留结果以便界面显示判定。
- **使用：** `QuizRunner`，学习者点击「检查」时。
- **说明：** `acceptedAnyway` 只会**抬高**判定，绝不会压低。确定性检查拥有「正确」这一判定：只要答案与目录所说的一致，就不会去问模型，也没有模型能把它拿走。

  **只有条目的首次作答会到达回调**，而且现在整场会话下来每个条目也只会到达一次——`_recordedItems` 集合就是执行这一点的东西。SM-2 评的是回忆的好坏：一分钟内第三次才答对的条目并没有被回忆起来；而在一份卷子就同一个词问四道题的情形里，第一道才是没有被前三道预热过的那一道。生成的题根本不会到达调度器；但它仍然计入学习者看到的成绩，因为他确实作答了。

  即使卷子就同一个条目问了四遍，错题名单也只列它一次：这份名单是要告诉学习者去复习什么的，同一个词出现四次是一份更差的名单，而不是一份语气更重的名单。

### `void next()` <a id="next"></a>

- **种类：** 方法
- **用途：** 进入下一题，并把答错的重新排队。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 改变队列；通知监听者。
- **算法：** 丢掉当前题目；若 `requeue` 开着、它答错了，且其计分键的重排次数少于 `maxRequeues`，则放到队尾。
- **使用：** `QuizRunner`，学习者点击「继续」时。
- **说明：** 这种重复正是学习发生的地方，而上限则防止一个难缠的条目让会话永远结束不了。与 `answer` 刻意分开：判分之后题目仍留在屏幕上，因为没被展示正确答案的学习者只会再猜一次，而不是学会。以 `requeue: false` 创建的会话根本不做这件事。

### `void forfeit()` <a id="forfeit"></a>

- **种类：** 方法
- **用途：** 结束会话，剩下的题一律留作未答。
- **输入：** 无。
- **返回：** 无。
- **副作用：** 清空队列；追加 `answered: false` 的结果；通知监听者。
- **算法：** 对队列中每一道还没有首次结果的题目，记录一个否定结果和一条标为未作答的 `QuestionOutcome`；然后清空队列。
- **使用：** 计时部分，在计时归零时。
- **说明：** 与 `skip` 不同，剩下的题目**会**被记录——记为 `answered: false`，它既不是对也不是错。时间不够是关于这次作答的事实，把它藏起来会让每一个计时成绩都显得比实际好；把它当成答错则会让学习者显得比实际差。没有任何东西会到达 `onFirstAnswer`：一道没作答的题说明不了这个条目被回忆得如何，所以它绝不能推动任何调度。

### `void restore(Map<String, QuizAnswer> answers)` <a id="restore"></a>

- **种类：** 方法
- **用途：** 重放上一次作答时保存下来的答案。
- **输入：** `answers`，以 `scoreKey` 为键。
- **返回：** 无。
- **副作用：** 重新判定每一道被重放的题目；可能调用 `onFirstAnswer`；结束时通知监听者一次。
- **算法：** 从队首往下走，只要保存里有队首那道题的答案就作答并前进；遇到第一个没有答案的就停下。
- **使用：** 继续一场保存的模拟考试。
- **说明：** 是把答案重新判一遍，而不是恢复它们当时的判定，这样一次修正了答案键的内容更新也会应用到被继续的这份卷子上——否则就要带着一个已发布文件不再认可的成绩。保存里没有答案的题目留在队列中，这正是「继续」的含义。
