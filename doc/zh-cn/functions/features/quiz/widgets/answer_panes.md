# lib/features/quiz/widgets/answer_panes.dart

作答用的控件：四个选项、一个文本框，或可点击排序的片段。

在调用处只用一个控件而不是三个——三种作答形状是唯一变化的东西，而适用哪一种是题目自身的属性。

组合中的选项和排序不保存在这里。它们作为 `pending` 从 [`QuizRunner`](quiz_runner.md) 传进来，每一次点击都通过 `onChanged` 上报，因此点击和键盘快捷键经由同一条路径改变同一份状态。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| [`remainingFragments`](#remainingfragments) | 顶层函数 | A | 按片段按钮显示的顺序，列出尚未放入的排序片段。 |
| [`AnswerPane`](#answerpane) | 类 | A | 构建一道题所需的控件。 |
| `_ChoicePane` | 类 | B | 每行一个选项，整行可点；选中项从 `pending` 读取。 |
| `_ChoicePane._option` | 方法 | B | 构建一个选项按钮，需要时为键盘编号，作答后加以标记。 |
| `_KeyNumber` | 类 | B | 选中某个选项的那个数字，低调绘制，并排除在语义之外。 |
| `_TypedPane` | 类 | B | 输入读音用的文本框，或者对于写出整句（`sentence`）是一整句的文本框，持有自己的焦点节点。 |
| `_TypedPaneState.initState` | 方法 | B | 在第一帧之后为文本框请求键盘焦点。 |
| `_OrderPane` | 类 | B | 可点击排序的片段；排序从 `pending` 读取。 |
| `_OrderPane._remove` | 方法 | B | 把一个片段从句子里取回。 |

## 文档

### `List<int> remainingFragments(QuizQuestion question, QuizAnswer? pending)` <a id="remainingfragments"></a>

- **种类：** 顶层函数
- **用途：** 列出排序题中尚未放入的片段。
- **输入：** `question` 和学习者的 `pending` 答案。
- **返回：** 选项下标，按剩余片段按钮从左到右的绘制顺序。
- **副作用：** 无。
- **算法：** 所有不在 `pending` 排序中的选项下标，按下标顺序。
- **使用：** `_OrderPane` 用它绘制片段按钮并编号，`QuizRunner` 的数字快捷键也用它。
- **说明：** 刻意让两者共用一个函数：按键 `3` 必须表示屏幕上的第三个片段，而数字会随着片段的放入而变化。

### `class AnswerPane` <a id="answerpane"></a>

- **种类：** 类
- **用途：** 构建作答所用的控件。
- **输入：** 题目、目前已组合的 `pending` 答案、是否已锁定、组合与提交的回调，以及 `showKeyHints`——为键盘给选项和片段编号。
- **返回：** 一个控件。
- **副作用：** 无。
- **算法：** 按题目的 `AnswerKind` 分派，并以题目身份作为 key——有 `questionId` 时用它，否则用 `itemId`，再加上模式。
- **使用：** `QuizRunner`。
- **说明：** key 对输入框很重要：题目切换时，输入了一半的字符串会被丢弃而不是带进下一题。它把 `questionId` 也算进去，因为一份卷子会围绕同一个词问好几道不同的题。选项和排序在这里不需要这样的重置，因为运行器在换题时会清空 `pending`。
  组合与提交是两个回调，因此点错可以纠正：选中一个选项只是选中，再做一个动作才提交。排序用点击而不是拖拽，因为在手机上一个片段宽的拖放目标是很难的手势，而点击可以再点一次撤销。**输入框在第一帧之后自己请求焦点**，而不是使用 `autofocus`：一旦路由中有任何东西持有焦点，`autofocus` 就会被忽略，而在一道选择题之后，持有焦点的正是运行器的快捷键节点。开启按键提示时，前九个选项和剩余片段带着选中它们的数字；这个数字被排除在语义之外，因为屏幕阅读器已经会朗读该选项。
