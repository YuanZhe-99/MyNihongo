# tool/src/zh_tw.dart

生成的繁体中文在内容文件里该放在哪里的那条规则。

一个小库，由 `convert_zh_tw.dart` 及其测试共用，持有两个内容键，以及那趟"在每个 `zh` 旁边加上
`zh_TW`"的遍历。它与转换器本身分开，因为**位置**规则和**转换**是两件事：由 OpenCC 决定字变成什么，
由这里决定它写在哪里、什么时候被删掉。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| `zhTwKey` | 常量 | B | 繁体中文文本写在哪个内容键下。 |
| `zhKey` | 常量 | B | 简体中文文本撰写在哪个内容键下。 |
| [`withTraditional`](#with) | 函数 | A | 在每个简体字符串旁边加上一个生成的繁体字符串。 |
| `_convertValue` | 函数 | B | 转换一个 `zh` 值，无论它是字符串还是字符串列表。 |
| `openCcDirectory` | 常量 | B | OpenCC 词典相对于仓库根目录放在哪里。 |

## 文档

### `Object? withTraditional(Object? json, String Function(String) convert)` <a id="with"></a>

- **种类：** 函数
- **用途：** 在解码后的内容文件里，为每个简体字符串旁边加上一个生成的繁体字符串。
- **输入：** `json`——`jsonDecode` 返回的任何东西；`convert`——简体到繁体的转换。
- **返回：** 同一个结构，凡有 `zh` 的地方都设好了 `zh_TW`。
- **副作用：** 无——构建的是一个新结构，输入不被修改。
- **算法：** 遍历解码后的结构。在每个 map 上按顺序重建它，在 `zh` 键之后立刻写入转换好的 `zh_TW`；
  丢掉前面已经没有 `zh` 的那些遗留 `zh_TW`。对列表和 map 递归。
- **使用：** `convert_zh_tw.dart`，每个内容文件一次。
- **注意：** `zh_TW` 写在 `zh` 的**紧后面**，已有的会被替换。这正是工具幂等的原因：对它自己的输出重
  跑一次会得到逐字节相同的文件，所以输入没变的重建留下的是空的 `git diff`——而这正是让"有没有人忘了
  跑它"成为一个能回答的问题的原因。

  一个 `zh` 已经被删掉的 `zh_TW` 会跟着一起消失，因为**生成的文本不得比它的来源活得更久**。留着
  它，就是一段没有任何东西可以核对的繁体中文，而 `content_zh_tw_test.dart` 也就无从比较。

  `_convertValue` 兼容两种形状，因为内容把释义存成列表、把说明存成字符串。两种都走同一个地方，所以
  哪一种都不会被悄悄跳过。

  一个字符串在各处命名同一个区域设置——ARB 文件是 `app_zh_TW.arb`，存储的偏好是 `zh_TW`，而这是内容
  键——所以在一个地方学会这个标签的读者，在三个地方都学会了。
