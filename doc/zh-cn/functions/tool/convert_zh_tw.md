# tool/convert_zh_tw.dart

重新生成内置内容里的繁体中文文本。

改动任何简体中文文本之后都要运行它。**内容里的每一个 `zh_TW` 字符串都由它旁边的 `zh` 生成，从不手
工编辑**——`test/content_zh_tw_test.dart` 会比较两者，一旦不一致就失败，所以忘记运行是一次红色测试，
而不是一次无声的分歧。

这个工具是幂等的：第二次运行留下空的 `git diff`，这正是让"有没有人忘了跑它"成为一个能回答的问题的
原因。手写的例外是 `lib/l10n/app_zh_TW.arb` 与 `assets/content/prompts/`，本工具不碰它们——界面文字
和提示词由人来翻译，因为转换出来的界面读起来像机器写的，而转换出来的提示词是没人检查过的指令。

用法：`dart run tool/convert_zh_tw.dart`，测试时可用 `--opencc <dir>` 与 `--assets <dir>`。

## 声明

| 声明 | 种类 | 层级 | 用途 |
|---|---|---|---|
| library header | library doc | B | 重新生成内置内容里的繁体中文文本。 |
| [`main`](#main) | 函数 | A | 走遍内容目录，重写有变化的文件。 |
| `_rewriteCatalog` | 函数 | B | 按词汇目录自己已提交的形状重写它。 |
| `_rewritePretty` | 函数 | B | 用标准的两空格编码器重写一个手写内容文件。 |
| `_writeIfChanged` | 函数 | B | 只在内容确有不同时才写文件。 |

## 文档

### `Future<void> main(List<String> args)` <a id="main"></a>

- **种类：** 函数
- **用途：** 走遍内容目录，重写有变化的文件。
- **输入：** `args`——`--opencc <dir>` 与 `--assets <dir>`，两者都是给测试用的。
- **返回：** 无；设置退出码。
- **副作用：** 重写 `assets/content/` 下的文件。
- **算法：** 加载 OpenCC 词典，然后走一份**硬编码的、非递归的**内容目录清单，词汇目录交给
  `_rewriteCatalog`，其余交给 `_rewritePretty`。最后报告有多少文件发生了变化。
- **使用：** 内容改动之后手工运行；`test/content_zh_tw_test.dart` 间接依赖它，但检查的是结果而不是
  运行这个工具。
- **注意：** 那份目录清单是硬编码且扁平的，不是递归遍历。这正是练习题文件叫
  `drills/n5-reading.json` 而不是 `drills/n5/reading.json` 的原因——扁平布局在这里只花一条、在
  `content_zh_tw_test.dart` 里只花一条，而嵌套布局两边各要五条。新增一个内容目录必须同时加进两份清
  单，否则它的繁体文本就悄悄地永远不会被生成。

  词汇目录经由 `encodeCatalog` 保持它每行一条的编码，与导入器写它时用的是同一个函数，所以运行这个
  工具绝不会把 7,744 条词条重排成另一种形状。其余文件用的是本系列每个 JSON 文件都用的两空格编码
  器，所以第一次运行会把文件重排一次，之后每一次都是空操作。

  `_writeIfChanged` 跳过内容相同的写入以保留文件时间戳，这样监视资产的构建系统就不会被一个什么都没
  改的工具吵醒。
