# 句子分析

一个输入的日语句子如何变成词、结构、语法点和可能的问题。这里的一切都是确定性的、离线的、有单元测试的。没有模型，也没有网络；输入只有内置词汇、内置功能词表，以及几页规则。

流程是 `分词 → 分块 → 匹配语法 → 检查`，由 `SentenceAnalyzer` 串起来。每个阶段都是独立的文件和独立的测试。

## 1. 分词——词格，而非切分

日语没有空格，因此分词是一次搜索。分词器在每个字符位置提出它能给出的所有读法，为每一种定价，然后用动态规划取整句最便宜的路径。

**为什么不用贪心最长匹配。** 贪心在目录自带例句上就会出错：ここではなして 应切成 ここ/で/はなして 还是 ここ/では/なして，取决于后面是什么，而从左到右的一趟扫描无从得知。代价还让各种取舍显式且可测试，而不是藏在循环顺序里。

### 会提出哪些候选

| 候选边 | 来源 |
|---|---|
| 功能词 | 内置词表——助词、系动词各形、助动词、形式名词 |
| 目录词 | 词汇表，按书写形式**或**假名读音匹配 |
| 助动词**加它前面的词干** | 活用还原，见 §2——这是覆盖两者的一条边 |
| 裸的连用形词干 | 活用还原，用于 食べに行く 和 話し方 |
| 数字串 | 半角数字、全角数字，或 〇一二三四五六七八九十百千万 |
| 片假名串 | 任意最长串，当没有别的候选覆盖它时 |
| 标点 | 固定集合 |
| 单个未知字符 | 始终提出，使路径总能到达句尾 |

### 代价

用整数，这样 fixture 不会因四舍五入而漂移。越低越好。

| 候选边 | 代价 | 原因 |
|---|---|---|
| 功能词 | 8 | 同时是两者的表层——は、に、から——绝大多数情况下是功能词 |
| 目录词 | 10 | 基准 |
| ……经由假名读音 | +4 | ます 是 増す 的读音；在 勉強しています 中那样读会让句子丢掉动词 |
| ……数字之后的量词 | −3 | 量词本来就是这么用的 |
| ……没有数字的量词 | +5 | 本 是"书"的时候远多于它是细长物的量词 |
| 词干 + 助动词 | 12 | 词本身的代价加上助动词的 2 |
| 裸的连用形词干 | 14 | 高于真词，因此真词绝不会被恰好合适的词干挤掉 |
| 数字串 | 6 | |
| 片假名串 | 15 | 外来语或人名：不免费，但远比让汉字无人解释便宜 |
| 标点 | 1 | |
| 未知假名 | 30 | 多半是目录中某个词的一部分 |
| 未知汉字 | 40 | 真正的缺口 |

覆盖词干的边**从词干开始**，而不是从提出它的助动词开始，这样最短路径才能把整个动词与其他方案放在一起权衡。搞错这一点正是本流程的第一个 bug：見ました 被解析成未知的 見 加上无人解释的 ました。

### 规范化

全角 ASCII 转 ASCII，表意空格转空格，使输入法无法改变结果。**假名和汉字在其余方面保持原样**——与发音评分不同，分析器需要拿到原本的字体，因为大多数词边界正是靠汉字才看得见。

## 2. 活用还原——反向进行，并对照词典确认

功能词表中的每个助动词都声明了它所接的词干形态：ます 接连用形，た 接て形词干，ば 接え段词干，かった 接形容词词干。给定形态和它前面的字符，还原器回答哪些目录词条可能产生了它们。

反向进行让表保持很小。正向看，每个活用类有十几种形式；反向看，每种形态对每个类只是一次段位变换——而且**词典会否决一切不是词的结果**，因此规则可以放宽。

| 形态 | 规则 | 示例 |
|---|---|---|
| 连用形 | 一段 +る；五段 い段 → う段 | 行き → 行く |
| 未然形 | 一段 +る；五段 あ段 → う段，う 结尾用 わ | 買わ → 買う |
| て形词干 | 一段 +る；っ → う/つ/る **及 く**（行って）；し → す；い → く | 買っ → 買う |
| て形词干（浊音） | ん → ぬ/ぶ/む；い → ぐ | 飲ん → 飲ぬ、飲ぶ、飲む → 只有 飲む 是词 |
| え段词干 | 一段；五段 え段 → う段 | 行け → 行く |
| お段词干 | 五段 お段 → う段 | 帰ろ → 帰る |
| 形容词词干 | 词干为词元去掉 い；いい 从 よ- 活用 | 忙し → 忙しい |

する 和 来る 没有段位，因此按精确词干列表匹配。**精确**很关键：早先的版本用 `endsWith` 判断，于是 映画を見まし 被还原成 する——一条边以一个动词的价钱吞下半句话，而最短路径当然会选它。

### 语态是以「合成形」而不是「链」的方式加入的

被动、可能、使役与使役被动**在功能词表里逐条列出**，每个合成形一条：られます、させました、せられて，以及另外六十多条。这看上去与上面的段位表重复，但它本来就是对的形状。

原因是：这个去活用器只在**一个**助动词后面还原**一个**词干。它没有「助动词后面还能再接助动词」的概念，而 食べられませんでした 有四个。要教会词格做链式分析，就得把 られる 建模成一个独立的动词，并让搜索去组合词素——那是另一种算法，而且在那种算法里，一条错误的路径代价是整句话，而不是一条边。

逐条列出是同一笔交易的另一端。词表多出上百行，由脚本写出；每一行仍然明确声明它接在哪种词干形态之后，因此别处什么都不用改；词元报告的活用形就是整条链，因为这一条本身就写明了它们。代价是：没有被列出的形式将完全无法识别，而不是由零件拼出来。

**这是怎么发现的：** 在做这些之前，行かせます 解析出来没有任何未知词元——它被解成 行 + か + せ + 増す：四个真实的词，加在一起是胡话。撰写门禁只拒绝未知词元，所以它通过了。**由已知的词组成的错误解析**，正是门禁与 `sentence_analyzer_test` 都看不见的失败方式，也正因如此，N4 内容在合并前是被逐句手工探查过的。

标注为 `suru-verb` 的名词后面跟着 し 时**不**在这里查表。目录里有 勉強，没有 勉強する，因此凭空造出这个复合词会让词典里出现目录打不开的词；改由分块器把它们重新合并。

## 3. 分块——文节与右侧中心的猜测

文节是一个实词加上所有依附于它的成分。当一个词元是助词、系动词、助动词或后缀；或是数字之后的量词；或是 `suru-verb` 名词之后的 する；或是て形之后的动词（这是普通动词充当助动词的唯一场合）时，它并入当前打开的文节。

依存关系采用标准的右侧中心规则，一律向右看：

1. 修饰名词的文节——の、连体词、简体形容词、な、数字加量词——依附到后面最近的**体言**文节。
2. 其余依附到后面最近的**谓语**文节。
3. 两者皆无时依附到下一个文节。最后一个文节是根。

修饰名词的文节**不是**谓语，即使它的中心是形容词：新しい映画を見ました 只有一个谓语，而且不是 新しい。没有这条规则时，时态检查会在 私は昨日……新しい映画を見ました 上误报，因为 昨日 依附到了 新しい。

不建模小句边界。一个文节可能跨过て形或から依附，通常是对的，偶尔不对——UI 把结果呈现为猜测，应用中也没有别的部分依赖它。

## 4. 语法匹配——落在词元边界上

第一阶段把语法点的 `match` 字符串当作原句的子串来匹配，参考页面中的 `content_links.dart` 至今如此。这错得足够频繁以致会被注意到：〜は 会匹配到任何长词内部的 は。

匹配器用同样的字符串去比对**词元序列**：匹配必须在词元边界开始和结束。于是 〜は 只在分词器判定存在助词 は 的地方匹配，而不会落在 はな 内部。单字符的匹配形式只有在句子中确实存在这样拼写的助词词元时才放行。

重叠：严格包含在更长匹配中的匹配会被丢弃，因此 〜てもいいです 只报告一次，而不是它自己加上 です。跨度相同时两者都保留——在那一步没有依据偏向任何一方。

**不需要改动内容。** 语法 schema 仍是版本 2，现有的 `match` 列表就这样变得有用。

## 5. 检查——五项，每一项都写成尽量保持沉默

每条结论都是**可能的**问题，UI 也这样表述。分析器没有关于作者意图的模型：它只能看出某个搭配不常见，而不能断定它是错的。学习者在没错时被告知错了，就会不再看这一节，真正有价值的结论也一起被浪费。

| 检查 | 触发条件 | 保持沉默的条件 |
|---|---|---|
| 助词框架 | 一个を标记的文节依附到目录标注为 `intransitive` 且非 `transitive` 的动词 | 动词同时带两个标注（很多都是），或属于 `path-verbs` 集合——公園を歩く 是对的 |
| な/の 混淆 | な形容词接 の，或名词接 な，且后面是名词 | 该词同时标注为名词与な形容词，或是 `no-adjective` |
| 时态与时间词 | `time-past` 词依附到非过去谓语，或 `time-future` 词依附到过去谓语 | 谓语是意志形、たい 或て形；时间词带 から 或 まで |
| 缺少系动词 | 最后一个文节是裸体言，且句子有 ≥ 2 个文节并含 は 或 が 文节 | 单个名词——标题、标签、对问题的回答 |
| 形容词当动词用 | 保留项；词格让 高いません 无法成立而非可解析，因此目前报告的是未知词元 | — |

最多报告三条：触发更多的句子更可能是分词出错，而不是真的错那么多。

## 已知缺口

- **目录缺少的词汇。** 母、顔、東京、汉字形式的 鞄 以及 速い 不在生成目录所用的 JLPT 列表中，因此使用它们的例句会保留一个未知词元。它们列在 `test/fixtures/sentence/allowed_unknown.json` 中，上限 20，每条都注明需要它的例句。修复其中一条意味着把该词加入源列表并重新生成 `vocab.json`。
- **N4 以上没有覆盖。** 词表覆盖的是 N5 与 N4 所教的内容。N3 及以上会引入 〜ざるを得ない、〜ようがない、完整的自谦与尊敬体系等形式，它们没有被列出，会以未知词元的形式出现。
- **错误的解析不等于失败的解析。** 这里所有自动检查问的都是「这句话是否产生了未知词元」。一句被解析成四个真实词语、组合起来却毫无意义的话，能通过全部检查。唯一的防线是去读词元 chip——这也是句子实验室存在的理由之一。
- **没有形态分析模型。** `PLAN.md` M2.3 提出移植 TinySegmenter 以提供边界提示。事实证明不需要：在 7,700 词条加功能词表的规模下，词格自己就能覆盖所有随应用发布的例句，而移植会为一项取舍加分引入一个需要维护的模型。已记入决策日志。
- **语法点上没有词元/词性规则 schema。** 同样是提出过、同样不需要——见 §4。
