# 发音评分

如何把一次朗读尝试与词条本身作对照。这里的一切都是确定性的、离线的、有单元测试的；本功能中唯一非确定性的部分是平台识别器，而在下面任何一步运行之前，它已经决定了自己听到了什么。

**本方法衡量的是可辨识度，而不是口音。** 识别器给出了一段转写；这里把这段转写与目标作对照。一个声调错误但音拍全对的学习者会得 100 分，UI 也明确这样说明。声调反馈需要声调词典和 f0 分析，在 `PLAN.md` 中属于第三阶段之后的候选项。

## 流程

```
目标读音     ─→ toHiragana ──────────────────┐
                                              ├─→ splitMorae ─→ 对齐 ─→ 差异 ─→ 分数
识别器文本   ─→ Lexicon.toKana ─→ toHiragana ┘
```

### 1. 解析汉字（仅对尝试一侧）

`Lexicon.toKana`（`lib/features/sentence/services/lexicon.dart`）从左到右扫描识别器的答案，在每个位置取**最长**匹配的目录词头，并用该词条的读音替换它。当词条写作 とうきょう 时，Android 的识别器会答「東京」；逐字对照会把一次完美的朗读判成零分。

目录不认识的片段会**原样保留**。它随后作为独立条目进入音拍列表并消耗一次编辑，这是诚实的结果：应用读不出它，假装读得出只会虚高分数。

规范化在得到整个结果之后才施加，绝不在循环内部进行——`ー` 的元音取自它前面的音拍，因此逐字符规范化会把它丢掉。

### 2. 规范化两侧——`toHiragana`

`lib/features/kana/models/kana_text.dart`：

| 输入 | 变为 | 原因 |
|---|---|---|
| 片假名 | 平假名 | 字体是识别器选的，不是学习者选的 |
| `ー`（以及 `－`、`—`） | 前一音拍的元音 | コーヒー 和 こおひい 是同一个词、同样的读法 |
| 全角 ASCII | ASCII | 各识别器对拉丁字母和数字的宽度处理不一 |
| 空白、`。、・？！` 及西文标点 | 丢弃 | 标点是识别器的决定，不是学习者说出来的 |
| 汉字 | 不变 | 本函数读不了汉字；那是第 1 步的事 |

### 3. 切分为音拍——`splitMorae`

音拍是日语节奏的计数单位，也是听者实际评判学习者的单位。

- 小书假名（`ゃゅょぁぃぅぇぉゎ`）并入它前面的音拍：`きょ` 是**一个**音拍，不是两个。
- `っ` 和 `ん` 独立成拍。两者都是完整音拍，漏掉任何一个正是评分要指出的错误——`がっこう` 说成 `がこう` 必须有代价。
- 其余非假名字符各自成为一个条目，因此仍会消耗一次编辑。

### 4. 对齐——带回溯的 Levenshtein

在两个音拍列表上做标准编辑距离矩阵，然后回溯记录每一步发生了什么：`correct`、`substituted`、`missing`（目标里有、尝试里没有）或 `extra`（尝试里有、目标里没有）。规模很小——一个长例句也只有几十个音拍——所以平方级矩阵不值得优化。

**回溯遇到平局时优先取替换**，而不是一次删除加一次插入。说错了一个音拍的学习者应当看到一个错误音拍，而不是一处删除挨着一处新增。

### 5. 计分

```
分数 = round(100 × (1 − 编辑数 / max(目标音拍数, 1)))，并夹到 0…100
```

其中"编辑数"是所有不为 `correct` 的差异条目。几个刻意的性质：

- **分母是目标长度**，因此多余音拍会被扣分，同时也不会让一长串胡言乱语得到零分以上——夹取负责这一点。
- **空白尝试得 0 分**，且每个目标音拍都报告为缺失。这正是"什么都没听到"该有的样子；识别服务会在到达此处之前把空的最终结果转为 `noMatch` 失败，因此实际中学习者看到的是提示而不是零分。
- 分数是**次要输出**。练习表首先呈现差异；分数只是同一对齐结果的单数字摘要，而且只在尝试不完美时显示（完美时显示的是一句话）。

## 演算示例

目标 `がくせい`，听到 `がくせえ`：

| # | 目标 | 听到 | 操作 |
|---|---|---|---|
| 1 | が | が | correct |
| 2 | く | く | correct |
| 3 | せ | せ | correct |
| 4 | い | え | substituted |

四个目标音拍中有一处编辑 → `round(100 × (1 − 1/4))` = **75**。
