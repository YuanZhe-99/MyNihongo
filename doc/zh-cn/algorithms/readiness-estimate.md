# 备考程度估计

应用如何决定要不要说学习者看起来已经准备好考这个级别。这里是推导，不是描述，因为其中几乎每一个选
择都是"拒绝说某句话"，而后来的一次改动很容易悄悄把这个估计变成它当初刻意避免成为的东西。

代码在 `lib/features/drills/services/weakness_report.dart`（最近的卷子说明了什么）和
`lib/features/drills/services/readiness_rules.dart`（应用愿意据此声称什么）。两者都是纯函数，所以
这一切都不需要设备就能测试。

## 算不出来的东西

JLPT 不是按原始分计分的。JEES 用一套不公开的等值换算处理每个计分组，同样的原始分在不同场次可以换
算出不同的分数。**没有任何应用能算出 JLPT 成绩**，而在 JLPT 几个字母旁边印一个数字的应用，等于
在邀请学习者围绕一个没人能负责的数字做打算。

**能**算的是本应用所写题目上的正确率。诚实的呈现方式是一个档位，说明就放在旁边，任何地方都不出现
数字：

```
unknown      作答量还不够，什么都说不了
notYet       测得出来，但还不到
close        测得出来，已经接近
ready        测得出来，并且稳定地过线
unmeasured   本设备根本无法测量
```

界面会把"这是根据你在本应用中的练习推算的估计，不是官方 JLPT 成绩。"和档位放在同一段里，而不是藏
在提示气泡后面。

## 窗口

报告基于学习者**自己级别的最近五次作答**构建，并且每次读取都重新计算。什么都不存。

这就是"学习者能改变的报告"和"甩不掉的判决"之间的区别。如果统计所有做过的卷子，四十份旧卷会淹掉五
份最近的好卷，这个数字就不再对努力有反应——而它恰恰是在这时候才开始重要。

## 什么算数，什么不算

每一道作答过的题会往三处统计各加一个结果：它所属的部分、它的大问，以及它关联的每一个目录条目。

| 情形 | 处理 | 原因 |
|---|---|---|
| 答对或答错 | 计入 | 估计所依据的数据点。 |
| 未作答（`-1`，时间到了） | **完全不计** | 是时钟把题目拿走的。把超时读成学习者日语上的漏洞，会让他们去学错误的东西。 |
| 内置文件里已经没有的题 | 跳过 | 少一个数据点是诚实的代价；记进去则会把薄弱点算在一个应用已经无法命名的大问上。 |
| 其他级别的作答 | 不在窗口内 | 这个估计只针对一个级别。 |

一次作答里只保存**输入**——问了哪些题、答了什么——所以部分、大问和目录条目都是读取时从内置文件连接
出来的，内容更正会同时反映到报告和历史里。

## 从统计到档位

对每个计分组，把组内各部分相加，得出一个档位：

```
asked < 20                            -> unknown
accuracy >= 0.70                      -> ready
accuracy >= 0.55                      -> close
otherwise                             -> notYet
```

二十是一个分界点：低于它，一份走运的卷子就能改变档位，而一个来回摇摆的估计比没有还糟。`0.70` 与
`checkpointPassAccuracy` 是同一个数字：应用在开启下一个课程单元时已经认定十分之七意味着"这个学会
了"，同一个论断用两个阈值，等于应用在跟自己唱反调。

## 整体档位取最差的组

```
overall = 可测量的各组里最差的那个档位
```

不是平均。这照搬了考试自己的规则——**任何一个计分组不及格，整个级别就不及格**，别的组考得再好也一
样——而且这是真实 JLPT 计分里应用唯一能诚实复现的部分，因为它是一条规则而不是一个数字。

由此有两个后果，两个都是故意的：

- **只要有一个组是 unknown，整个估计就是 unknown。** 三个组里用两个组算出来的档位，是在描述一份
  没有人考过的卷子。
- **一个只有一组弱的强学习者不会被判为"可以了"。** 这不是估计苛刻，这就是真实结果会是的样子。

## 没有语音时的听力是 `unmeasured`，不是差

在没有日语语音合成的设备上，听力这一组根本没法问。它被标记为 `unmeasured` 并且**排除在整体档位之
外**，而不是当成不及格：学习者不是听力差，是设备问不了。卡片上会说明听力不在这个估计里。

它也不是 `unknown`——`unknown` 的意思是"多做几套卷子"，而这条建议这位学习者根本没法照做。

## 覆盖率只能往下压，不能往上抬

```
若 overall == ready 且 (该级别已接触条目 / 该级别全部条目) < 0.5:
    overall = close, cappedByCoverage = true
```

答得好说明的是关于被问到的那些题；对于一个词汇大多没见过的级别，它说明不了多少。这里的"接触过"指
的是存在学习记录——至少答过一次——而不是已经掌握，因为这只是一道防线，防的是把一个几乎没接触过的级
别判为"准备好了"，而不是第二个分数。

`cappedByCoverage` 被带到界面上，好让它能说出*为什么*。一个正确率九成的学习者看到没有任何解释的
"接近了"，读起来像 bug 而不像说明。

目录还没加载完时覆盖率取 1：启动慢的时候显示卷子挣来的档位，而不是一个没有解释的压制。

## 报告除档位之外的用途

最薄弱的条目——被问过至少三次、至少答错一次、正确率最低的在前、同分按 id 排序、最多十个——会交给复
习队列作为 `prioritized`。队列把它们排在其他到期内容之前，并在每一组内部按逾期程度排序。

它只负责**重排**。不往队列里加东西，也不从里面拿掉东西，所以一份空的、或者文件还没加载完的报告，
只是让学习者用回旧的排序，别无损失。

## 这些数字放在哪里

| 常量 | 值 | 文件 |
|---|---|---|
| `weaknessRecentAttempts` | 5 | `weakness_report.dart` |
| `weaknessMinAsked` | 3 | `weakness_report.dart` |
| `weaknessMaxPoints` | 10 | `weakness_report.dart` |
| `readinessReady` | 0.70 | `readiness_rules.dart` |
| `readinessClose` | 0.55 | `readiness_rules.dart` |
| `readinessMinAsked` | 20 | `readiness_rules.dart` |
| `readinessMinCoverage` | 0.5 | `readiness_rules.dart` |

计分组本身是内容而不是代码：它们来自 `assets/content/drills/structure.json`，该文件在自己的 source
字段里注明来源是 jlpt.jp。
