# 版本历史

MyNihongo!!!!! 的逐版本摘要。在改动一个行为之前理解它*为什么*存在很有用。

## 仓库注意事项

仓库的分支是 `main`。`origin` 远程仓库在第一次提交之前就已存在；`github` 远程仓库在初始化时添加。`myapps_data` 子模块最初固定到 `54fa8d7`，即包的 `v1.0.1` 标签之后两个仅文档的提交；现在固定到 `v1.0.2` 标签，其中包含本应用所需的 UTF-8 下载修复。

## 版本

- `0.3.1` — 2026-09-04。Phase 3 设计过却一直没写的三件事，以及一个终于补齐的目录。

  **情景课。** 单元可以以一段情景对话结尾：六到八行，每行一个说话人，其中一到两处脚本会停下来问学习者该说什么。每一行台词和每个候选回答都可以朗读。已为 N5 单元 1–4 和 N4 单元 1–2 编写；没有情景的单元不显示按钮。

  答错不会结束对话，也不会让对话分叉。脚本是线性的，学习者说了什么只改变结尾的统计，别的都不改——说错一句就中断的对话，教不会人该说什么。这里也不碰调度器：从三个里挑一个不是回忆，而回忆已经由单元自己的练习会话来量。

  **AI 生成的题目**，需开启开关。单元会话会向模型索取最多三道关于本单元语法点的额外题目，且在会话**已经**显示之后才索取，所以等待模型永远不会拖慢第一题。它们的标注显示在题面上方、读题之前；回答它们永远不会进入 SM-2，因为一道可能是错的题不该改动真实的复习间隔。解析器有六种拒绝方式——没有 `Q:` 行、句子里没有挖空、选项不是四个、有空选项、两个选项相同、`Answer:` 指向不存在的选项——因为在屏幕上，猜出来的题看起来和手写的题一样权威。

  **写作练习可以进入了。** 这个页面在 `0.3.0` 就已发布，却没有任何入口；现在单元的写作题会打开它。

  **目录补齐了。** N2 语法（170 点）和 N1 语法（158 点）填满了最后两级的筹码；全部 7,744 个词都有中文释义，除一个例外都有例句；每个级别都有了自己的单元，共 65 个。

  | 级别 | 语法点 | 课程单元 | 中文释义 | 例句 |
  |---|---|---|---|---|
  | N5 | 81 | 9 | 667 / 667 | 667 / 667 |
  | N4 | 100 | 12 | 630 / 630 | 630 / 630 |
  | N3 | 150 | 14 | 1,650 / 1,650 | 1,650 / 1,650 |
  | N2 | 170 | 15 | 1,737 / 1,737 | 1,737 / 1,737 |
  | N1 | 158 | 15 | 3,060 / 3,060 | 3,059 / 3,060 |

  唯一的缺口如实留下而不是粉饰过去：ＯＫ 写作全角拉丁字母、读作オーケー，而词库按词头建立表面索引，分析器两种写法都够不到它，因此没有任何一句例句能通过检查。

  有 26 个 N1 语法点在与 N2 的 slug 冲突时被**删除而不是改名**。改名能保住数量，代价是同一个句型以两个 id 教两遍；数量只是表格里的一个数字，而重复是学习者真会遇到的东西。

  让 N1 能被解析，先得让分析器学会文言层：ぬ、ざる、べからざる、べからず、んとする、んばかり、や否や、すべ、こととて、〜つ〜つ、極まりない、極み、の至り、同然、関の山、ぐるみ、三昧、やら〜やら。这些本身**就是** N1 的语法点，例句躲不开，所以只能扩充功能词表；而词典恰好没有的普通词则反过来处理，改写句子。有两个失败是静默的，花了不少时间：功能词上的 `needs` 意思是「把我接到某个词干上」，因此对跟在完整辞书形之后的形式是错的；而 `particle-conj` 不是加载器认识的类别名。两者都会直接丢掉词条、任何地方都不报错，唯一的症状就是句子解析不出来。

  同时修复：ヶ 和 ヵ 现在能对齐了。它们位于片假名区块却不是片假名——三ヶ月 读作さんかげつ——被当作假名锚点时，它们要求读音里出现一个读音永远不会有的 ヶ，于是每一句带月份计数的句子都失败。

  **内容撰写现在是四个已提交的子代理定义**，每种草稿一个，这样模型与推理强度属于内容流本身，而不属于当时碰巧敲下的提示词。`AGENTS.md` 写明：可用模型发生变化时需要重新审视这两个键。

  N5 之后的全部内容仍然是**模型撰写、未经审校**的，每个这样的文件都在自己的 `source` 字段里如实记录。

  设备发现了两件测试发现不了的事。**生成的题根本没有到达过**：提示词资产是一个 `FutureProvider`，进入会话的路径上没有任何地方碰过它，而代码读的是它的 `.value`——在加载完成之前那是 null。任何地方都不报错；功能只是什么都不做，而第二次尝试反而会成功。四个练习调用点都是同样的读法，现在四个都走同一个会等待它的辅助函数。

  以及**学习者选的那句回答从情景课的记录里消失了**，让整段对话读起来像是对方自顾自地说了下去。现在它会以正确／错误的标记显示在原位。

  已验证：667 个测试、`flutter analyze` 无问题，以及在 Pixel 10（Android 17，release 构建）上：情景课从头到尾——每行的注音、分支、答错的那句留在记录里、对话继续、以及结尾的统计；从单元打开的写作练习及其题目与两个操作；还有单元会话从 12 题增长到 15 题（生成的题陆续到达），每一题都调用了 AICore。

  **尚未在设备上验证：** 生成题自身的标注，要答完十二道题才能看到。

- `0.3.0` — 2026-09-04。学习引擎：间隔重复、测验、学习路径、汉字上方的假名、每日提醒，以及一份终于越过 N5 的内容库。

  **学习，而不只是浏览。** 在 Phase 1 就已存在、却从未被写入过的记录字段上跑 SM-2，并有两处与教科书的偏离——那是推导出来的，不是假定的。围绕同一个内容库的十三种提问方式，随后又加了三种。一个学习者档案、一个按本地日历日判定的复习队列，以及一份从记录派生而非存储的每日新词额度。

  **一条学习路径。** 九个 N5 单元，每个都是一个主题。一个单元会构建它全部的题池，再从中抽取十二道，按「还没答对的东西」加权，每个条目至多一道——正是这一点让冷门题型的出现概率与常见题型相同，而不是取决于它的条目有多常见。单元测验达到七成即解锁下一单元，而且**锁定单元的测验仍然可以进入**，因为那正是已经掌握这些材料的人跳过去的方式。

  **汉字上方显示假名**，默认开启。内容库为每个词存一条读音、不存逐字读音，因此对齐是从两个字符串还原出来的——而在什么都对不上时它会拒绝，而不是猜。错误的对齐不是更难看的排版，它把假名印在了错误的字上。

  **每日提醒**，在打开之前一直关闭，内容是有多少项到期、或下一个单元是哪个。权限由开关请求、别处一概不请求，这条规则背后有一条测试，因为 M2.4 曾发布过一个一打开设置就请求麦克风的版本。

  **端侧 AI 多了两种用途**：为什么选的那项不对——扎根于目录自带的说明，并被禁止与之矛盾——以及按需生成的额外例句。两者都只在开关打开时出现，都带标注，都不保存。

  **内容库越过了 N5，而它是怎么长起来的，被明白地写了出来。** N4 语法（100 点）与 N3 语法（150 点）填上了自 Phase 1 起就空着的筹码。中文现已覆盖 N5、N4 与 N3 的每一个词——目录中 7,744 个词里的 2,947 个，此前是 669 个。517 个 N5 词有了例句，此前是 24 个。

  N5 以上的这一切都是由模型代理对着一道撰写门禁写出来的，**没有任何日语或中文母语者读过**。门禁能证明一个句子可以用应用自己的词典解析、读音与句子一致、所用 id 确实存在；它无法证明日文是否自然。每个这样的文件都写着 `"source": "model-authored (Claude), unreviewed"`，每条释义都保留 `reviewed: false`，`content-authoring.md` 写明了这些检查保证不了什么。另一条路是只发布 N5 而没有其余。

  为了让这些内容成为可能，得先教会句子分析器 N4 与 N3：被动、可能、使役与使役被动从来没有被解析过，而其中一些看上去像是解析了——行かせます 曾被解成四个真实的词、组合起来毫无意义，而这里没有任何自动检查看得见。约 130 个功能词之后，21 句 N4 探查句中有 20 句能解析，并且罕见词在词格里的代价现在高于常用词。

  **发布时的覆盖情况**，因为一张表比一句声明更诚实：

  | 级别 | 语法点 | 中文释义 | 例句 |
  |---|---|---|---|
  | N5 | 81 | 667 / 667 | 517 / 667 |
  | N4 | 100 | 630 / 630 | 0 / 630 |
  | N3 | 150 | 1,650 / 1,650 | 2 / 1,650 |
  | N2 | 0 | 0 / 1,737 | 0 / 1,737 |
  | N1 | 0 | 0 / 3,060 | 0 / 3,060 |

  本次还包含：M2.5 的繁体中文——它是被有意从 `0.2.1` 里留下来的；以及在 Z Fold 8 上发现的三个设备问题：语音合成用设备自身的语言读日语、语音选择器没有任何试听方式，以及端侧 AI 用同一句话报告四种不同的原因。

  验证：640 项测试通过，`flutter analyze` 无问题，并构建了一个 debug APK 以检查清单合并。

  **未在设备上验证：** 提醒的实际触发、学习路径与单元测验、手机屏幕上的假名注音渲染，以及两项新的 AI 操作。本次发布没有任何内容在真机上运行过。

- `0.2.1` — 2026-09-03。句子实验室的端侧 AI 辅助，也是第一个在真机上验证过的版本。

  一台 **Pixel 10** 到位了，这既是本版本得以成立的前提，也改变了本条目其余部分的诚实程度：`0.2.0` 只通过测试接缝验证过，而其中两项行为在真机一跑起来就被证明是错的。

  端侧 AI（`PLAN.md` M2.4）：在设置中打开**端侧 AI 辅助**后——在学习者打开之前一直关闭——句子实验室可以用更多文字解释它自己的一处发现、解释整个句子，并给出改写建议。解释来自 ML Kit 的 Prompt API，改写来自其校对 API，两者都通过 Android AICore 在手机上运行。这个开关是**闸门而不是过滤器**：关闭时方法通道根本不会被调用。生成的一切都显示在带「生成」标注的卡片中，位于它所评论的确定性发现之下，且不会被保存、同步或写入目录。提示词是一份带版本号的内容资产，以应用自身的分析和目录自带的语法说明为依据，因此解释不会偏离语法页所教的内容。唯一的网络使用是模型下载，由 AICore 系统服务在学习者点击「下载」时执行；隐私政策已就此说明。AICore 通过应用自己的 Kotlin 通道而非插件访问，理由与锁定 `file_picker` 和 `speech_to_text` 的 Kotlin Gradle 插件问题相同，`minSdk` 因此升到 26。

  两个开发主机不可能暴露、在手机上发现并在此修复的缺陷：

  1. **R8 把 ML Kit 压缩成了 `NullPointerException`**，只出现在 release 构建，应用把它报告为「本设备不支持」——而那台手机完全支持。debug 构建一切正常，这正是它此前不可见的原因。`android/app/proguard-rules.pro` 现在保留 `com.google.mlkit.**`；只保留 `genai` 那几个包是不够的。
  2. **打开设置页就会弹出麦克风授权**，这是 `0.2.0` 的缺陷：语音识别状态行会去问识别器是否可用，而「问」正是让 Android 申请麦克风的动作——这违背了 `0.2.0` 文档中「弹窗绝不会毫无解释地出现」的承诺。设置页现在先检查权限，状态行也多了第三种「尚未检查」的说法，它与「本设备没有识别器」不是同一个判断。

  验证：`flutter analyze` 无问题、348 项测试、release APK，以及在 Pixel 10 上以英文与简体中文完整实测了整个 AI 功能。**仍未在设备上验证：**语音合成与语音识别本身——本次发布未覆盖它们——以及 macOS，它至今从未编译过。

- `0.2.0` —— 2026-09-03。第二阶段：应用会说、会听，也会读一个句子。同时提前加入了 Windows 与 macOS 工程，因为发音相关的工作需要一台能运行应用的机器，而开发主机没有 Android 设备。

  在本机通过 `flutter analyze`（无问题）、297 项测试，以及 Android APK 与 Windows 可执行文件两种 debug 构建验证，后者已启动并检查。**未在设备上验证：**本机没有日语语音合成语音、没有日语语音数据、也没有 Android 手机，因此音频通路与识别器本身只通过它们的测试接缝被驱动——本机实际显示的是"无语音"和"无识别器"状态，而该状态是有覆盖的。macOS 从未编译过：这里没有 Mac。

  Windows 与 macOS（`PLAN.md` 第五阶段，提前落地）：两个工程、一份用同一脚本构建 x64 与 ARM64 的 `installer.iss`、一个 `msix_config`、桌面启动图标，以及一个在 1000×720 打开的单实例 Windows runner——这个宽度足以让参考列表已呈双列，而那正是桌面端值得查看的布局。CI 刻意只跑 Android；桌面目标用于本地开发。`flutter_tts` 的 Windows 插件需要 `PATH` 上有 `nuget.exe`，这现在是有文档的前置条件。设置页仅在桌面端显示存储位置：在手机上那个路径指向用户既无法浏览也无法处置的沙盒。所有平台分支现在都集中在一个文件 `shared/utils/platform_capabilities.dart` 中，读取 `defaultTargetPlatform`，使仅 Android 的分支在 Windows 主机上仍可测试。

  语音合成（`PLAN.md` M2.1）：假名、词头和每个例句都由设备自身的引擎朗读，长按五十音图任意格子也可。始终优先使用假名读音而非汉字表层，因此引擎无法猜错读法。同一时刻只有一段朗读，并对外公布，使正在播放的按钮显示停止图标而其余保持静止。设置中提供速度滑块与日语语音选择，两者都是设备本地的。没有安装日语语音时，按钮被禁用而非隐藏，设置页提供一个打开系统语音设置的按钮。

  语音识别与发音反馈（`PLAN.md` M2.2）：读出一个假名、单词或句子，看看哪些音拍对上了。识别**默认只用离线**——在 Android 上这意味着没有安装日语模型时请求会失败，而不是悄悄发往服务器，练习表把该失败转成一条同时给出两种修复方式的提示。设置中一个默认关闭、以缺失键存储的开关，是内容被发往系统语音服务的唯一途径；除 WebDAV 同步外，它是唯一会让内容离开设备的设置。麦克风在首次使用时经由应用自己的说明申请，绝不在安装时申请。评分把两侧规范化为平假名音拍，并用一条平局时优先取替换的编辑路径对齐，因此说错一个音拍读起来就是一个错误音拍；尝试一侧会先经由新的目录索引改写，因为当词条写作汉字时识别器也会答汉字。逐音拍的差异是主要输出，分数只是它的摘要。自录回放已推迟：它需要与识别器同时使用麦克风，而没有设备无法验证。

  句子实验室（`PLAN.md` M2.3）：输入一个句子，看到词、什么修饰什么、用到了哪些已收录语法，以及有什么看起来不寻常。分词用带代价的词格加最短路径，而不是贪心最长匹配，因为一串假名怎么切取决于它后面是什么。活用还原反向进行——每个助动词声明它所接的词干形态，内置词汇否决一切不是词的提案，因此一个浊音て形词干可以提出三个活用类而只留下真正存在的那个。语法点针对词元序列而非原始文本匹配，这不需要改动内容，也阻止了单字符助词匹配到更长词的内部。四项检查报告**可能的**问题，每一项都带着让它保持沉默的豁免条件。新增内容：一张约九十条的功能词表，包含助词、系动词各形、助动词与形式名词，带 `fw:` id，对同一表层优先于词汇表。最关键的测试是：随应用发布的每个例句都能无未知词元地解析；词汇表确实缺少的五个词列在一份有上限的 fixture 中，每条都注明需要它的例句。M2.3 设计中有三处因不必要而放弃、一处推迟，均记入 `PLAN.md` 的决策日志：不移植 TinySegmenter、不新增词元/词性匹配 schema、在任何窗口尺寸下都是单列，以及把 AICore 增强留作一个没有实现的 `SentenceEnhancer` 接缝。

- `0.1.0` —— 2026-09-03。首个版本：第一阶段的参考应用。M1.0 到 M1.4 在一天内完成；下面四段就是其中发布的内容，按落地顺序排列。

  在本机通过 `flutter analyze`（无问题）、174 项测试（含一项针对真实生成目录逐一走过每个标签的整机冒烟测试），以及 APK 与 App Bundle 两种发布构建验证。**未在设备上验证：**开发主机没有模拟器也没有连接手机，因此折叠屏截图检查与针对真实 WebDAV 服务器的同步尚未完成。黄金记录以内存中的服务器覆盖了同步、备份与 ZIP 协议。

  项目骨架（`PLAN.md` M1.0）——Android 目标，带本系列自适应布局和导航栏的五标签外壳，从 MyAnime!!!!! 移植并把数据抽出为目录模型的五十音图，内置的单词与语法种子内容（24 个 N5 单词、8 个 N5 语法点，英语和简体中文）及浏览页面，带未知字段保留的同步 `StudyRecord` 进度模型，`nihongo_progress.json` 数据模块和四个覆盖 `myapps_data` 的门面（facade），带主题 / 语言 / 存储 / 关于且在宽窗口上双栏的设置，英语和简体中文 UI，覆盖布局规则、页面、JSON 兼容性、模块契约和内容规则的测试，双语文档，每次推送到 `main` 都运行的 Android CI 工作流，以及带 iOS 默认 / 深色 / 着色变体的应用图标（`ios/` 文件夹仅为图标集搭建，CI 不构建它）。

  同步与备份界面（`PLAN.md` M1.1）：带手动同步、强制上传与下载的 WebDAV 配置页面，其设置行带实时状态副标题；通过内容库为每条记录命名、并让用户保留任一版本的冲突对话框；带自动备份、保留期限、按模块还原与还原后强制上传提示的备份页面；ZIP 导出与导入；覆盖三个引擎的黄金请求记录。进度 provider 改为 `StateNotifierProvider`，代表所有页面只订阅一次 `AutoSyncService`。随之落地的共享包修复：`WebDavClient.download` 现在解码 UTF-8 字节而不是 `response.body`——服务器未发送 charset 时 `package:http` 会按 latin1 解码，这会损坏每个含假名的下载记录 id。

  内容流水线（`PLAN.md` M1.2）：单词库扩充为跨 N5 到 N1 的 7,744 条，由 `tool/import_vocab.dart` 从 JMdict 与 JLPT 词表离线生成，24 个手写种子 id 保留为别名，任何进度都不会成为孤儿；81 个 N5 语法点；21 条假名教学注释；一个平文式罗马字转写器；以及为每个 N5 词机器撰写、尚未校对的中文释义。解析移到后台 isolate，目录查找改为映射。

  参考页面打磨（`PLAN.md` M1.3）：带示例单词的假名详情弹层，单词与语法例句之间的交叉链接，按设备记住的标签、等级筛选、假名字体与列数，以及参考列表上的列数控件。截图检查尚未完成：开发主机上没有模拟器。
