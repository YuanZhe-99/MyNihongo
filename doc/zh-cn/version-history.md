# 版本历史

MyNihongo!!!!! 的逐版本摘要。在改动一个行为之前理解它*为什么*存在很有用。

## 仓库注意事项

仓库的分支是 `main`。`origin` 远程仓库在第一次提交之前就已存在；`github` 远程仓库在初始化时添加。`myapps_data` 子模块最初固定到 `54fa8d7`，即包的 `v1.0.1` 标签之后两个仅文档的提交；现在固定到 `v1.0.2` 标签，其中包含本应用所需的 UTF-8 下载修复。

## 版本

- *未发布* `0.1.0`：项目骨架（`PLAN.md` M1.0）——Android 目标，带本系列自适应布局和导航栏的五标签外壳，从 MyAnime!!!!! 移植并把数据抽出为目录模型的五十音图，内置的单词与语法种子内容（24 个 N5 单词、8 个 N5 语法点，英语和简体中文）及浏览页面，带未知字段保留的同步 `StudyRecord` 进度模型，`nihongo_progress.json` 数据模块和四个覆盖 `myapps_data` 的门面（facade），带主题 / 语言 / 存储 / 关于且在宽窗口上双栏的设置，英语和简体中文 UI，覆盖布局规则、页面、JSON 兼容性、模块契约和内容规则的测试，双语文档，每次推送到 `main` 都运行的 Android CI 工作流，以及带 iOS 默认 / 深色 / 着色变体的应用图标（`ios/` 文件夹仅为图标集搭建，CI 不构建它）。

  同步与备份界面（`PLAN.md` M1.1）：带手动同步、强制上传与下载的 WebDAV 配置页面，其设置行带实时状态副标题；通过内容库为每条记录命名、并让用户保留任一版本的冲突对话框；带自动备份、保留期限、按模块还原与还原后强制上传提示的备份页面；ZIP 导出与导入；覆盖三个引擎的黄金请求记录。进度 provider 改为 `StateNotifierProvider`，代表所有页面只订阅一次 `AutoSyncService`。随之落地的共享包修复：`WebDavClient.download` 现在解码 UTF-8 字节而不是 `response.body`——服务器未发送 charset 时 `package:http` 会按 latin1 解码，这会损坏每个含假名的下载记录 id。
