# 版本历史

MyNihongo!!!!! 的逐版本摘要。在改动一个行为之前理解它*为什么*存在很有用。

## 仓库注意事项

仓库的分支是 `main`。`origin` 远程仓库在第一次提交之前就已存在；`github` 远程仓库在初始化时添加。`myapps_data` 子模块最初固定到 `54fa8d7`，即包的 `v1.0.1` 标签之后两个仅文档的提交；现在固定到 `v1.0.2` 标签，其中包含本应用所需的 UTF-8 下载修复。

## 版本

- `0.2.0` —— 2026-09-03。第二阶段：应用会说、会听，也会读一个句子。同时提前加入了 Windows 与 macOS 工程，因为发音相关的工作需要一台能运行应用的机器，而开发主机没有 Android 设备。

  在本机通过 `flutter analyze`（无问题）、297 项测试，以及 Android APK 与 Windows 可执行文件两种 debug 构建验证，后者已启动并检查。**未在设备上验证：**本机没有日语语音合成语音、没有日语语音数据、也没有 Android 手机，因此音频通路与识别器本身只通过它们的测试接缝被驱动——本机实际显示的是"无语音"和"无识别器"状态，而该状态是有覆盖的。macOS 从未编译过：这里没有 Mac。

  Windows 与 macOS（`PLAN.md` 第五阶段，提前落地）：两个工程、一份用同一脚本构建 x64 与 ARM64 的 `installer.iss`、一个 `msix_config`、桌面启动图标，以及一个在 1000×720 打开的单实例 Windows runner——这个宽度足以让参考列表已呈双列，而那正是桌面端值得查看的布局。CI 刻意只跑 Android；桌面目标用于本地开发。`flutter_tts` 的 Windows 插件需要 `PATH` 上有 `nuget.exe`，这现在是有文档的前置条件。设置页仅在桌面端显示存储位置：在手机上那个路径指向用户既无法浏览也无法处置的沙盒。所有平台分支现在都集中在一个文件 `shared/utils/platform_capabilities.dart` 中，读取 `defaultTargetPlatform`，使仅 Android 的分支在 Windows 主机上仍可测试。

  语音合成（`PLAN.md` M2.1）：假名、词头和每个例句都由设备自身的引擎朗读，长按五十音图任意格子也可。始终优先使用假名读音而非汉字表层，因此引擎无法猜错读法。同一时刻只有一段朗读，并对外公布，使正在播放的按钮显示停止图标而其余保持静止。设置中提供速度滑块与日语语音选择，两者都是设备本地的。没有安装日语语音时，按钮被禁用而非隐藏，设置页提供一个打开系统语音设置的按钮。

  语音识别与发音反馈（`PLAN.md` M2.2）：读出一个假名、单词或句子，看看哪些音拍对上了。识别**默认只用离线**——在 Android 上这意味着没有安装日语模型时请求会失败，而不是悄悄发往服务器，练习表把该失败转成一条同时给出两种修复方式的提示。设置中一个默认关闭、以缺失键存储的开关，是内容被发往系统语音服务的唯一途径；除 WebDAV 同步外，它是唯一会让内容离开设备的设置。麦克风在首次使用时经由应用自己的说明申请，绝不在安装时申请。评分把两侧规范化为平假名音拍，并用一条平局时优先取替换的编辑路径对齐，因此说错一个音拍读起来就是一个错误音拍；尝试一侧会先经由新的目录索引改写，因为当词条写作汉字时识别器也会答汉字。逐音拍的差异是主要输出，分数只是它的摘要。自录回放已推迟：它需要与识别器同时使用麦克风，而没有设备无法验证。

  句子实验室（`PLAN.md` M2.3）：输入一个句子，看到词、什么修饰什么、用到了哪些已收录语法，以及有什么看起来不寻常。分词用带代价的词格加最短路径，而不是贪心最长匹配，因为一串假名怎么切取决于它后面是什么。活用还原反向进行——每个助动词声明它所接的词干形态，内置词汇否决一切不是词的提案，因此一个浊音て形词干可以提出三个活用类而只留下真正存在的那个。语法点针对词元序列而非原始文本匹配，这不需要改动内容，也阻止了单字符助词匹配到更长词的内部。四项检查报告**可能的**问题，每一项都带着让它保持沉默的豁免条件。新增内容：一张约九十条的功能词表，包含助词、系动词各形、助动词与形式名词，带 `fw:` id，对同一表层优先于词汇表。最关键的测试是：随应用发布的每个例句都能无未知词元地解析；词汇表确实缺少的五个词列在一份有上限的 fixture 中，每条都注明需要它的例句。M2.3 设计中有三处因不必要而放弃、一处推迟，均记入 `PLAN.md` 的决策日志：不移植 TinySegmenter、不新增词元/词性匹配 schema、在任何窗口尺寸下都是单列，以及把 AICore 增强留作一个没有实现的 `SentenceEnhancer` 接缝。

- `0.1.0` —— 2026-09-03。首个版本：第一阶段的参考应用。M1.0 到 M1.4 在一天内完成；下面四段就是其中发布的内容，按落地顺序排列。

  在本机通过 `flutter analyze`（无问题）、174 项测试（含一项针对真实生成目录逐一走过每个标签的整机冒烟测试），以及 APK 与 App Bundle 两种发布构建验证。**未在设备上验证：**开发主机没有模拟器也没有连接手机，因此折叠屏截图检查与针对真实 WebDAV 服务器的同步尚未完成。黄金记录以内存中的服务器覆盖了同步、备份与 ZIP 协议。

  项目骨架（`PLAN.md` M1.0）——Android 目标，带本系列自适应布局和导航栏的五标签外壳，从 MyAnime!!!!! 移植并把数据抽出为目录模型的五十音图，内置的单词与语法种子内容（24 个 N5 单词、8 个 N5 语法点，英语和简体中文）及浏览页面，带未知字段保留的同步 `StudyRecord` 进度模型，`nihongo_progress.json` 数据模块和四个覆盖 `myapps_data` 的门面（facade），带主题 / 语言 / 存储 / 关于且在宽窗口上双栏的设置，英语和简体中文 UI，覆盖布局规则、页面、JSON 兼容性、模块契约和内容规则的测试，双语文档，每次推送到 `main` 都运行的 Android CI 工作流，以及带 iOS 默认 / 深色 / 着色变体的应用图标（`ios/` 文件夹仅为图标集搭建，CI 不构建它）。

  同步与备份界面（`PLAN.md` M1.1）：带手动同步、强制上传与下载的 WebDAV 配置页面，其设置行带实时状态副标题；通过内容库为每条记录命名、并让用户保留任一版本的冲突对话框；带自动备份、保留期限、按模块还原与还原后强制上传提示的备份页面；ZIP 导出与导入；覆盖三个引擎的黄金请求记录。进度 provider 改为 `StateNotifierProvider`，代表所有页面只订阅一次 `AutoSyncService`。随之落地的共享包修复：`WebDavClient.download` 现在解码 UTF-8 字节而不是 `response.body`——服务器未发送 charset 时 `package:http` 会按 latin1 解码，这会损坏每个含假名的下载记录 id。

  内容流水线（`PLAN.md` M1.2）：单词库扩充为跨 N5 到 N1 的 7,744 条，由 `tool/import_vocab.dart` 从 JMdict 与 JLPT 词表离线生成，24 个手写种子 id 保留为别名，任何进度都不会成为孤儿；81 个 N5 语法点；21 条假名教学注释；一个平文式罗马字转写器；以及为每个 N5 词机器撰写、尚未校对的中文释义。解析移到后台 isolate，目录查找改为映射。

  参考页面打磨（`PLAN.md` M1.3）：带示例单词的假名详情弹层，单词与语法例句之间的交叉链接，按设备记住的标签、等级筛选、假名字体与列数，以及参考列表上的列数控件。截图检查尚未完成：开发主机上没有模拟器。
