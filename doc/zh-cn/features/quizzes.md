# 测验

围绕同一个内容库的十三种提问方式、一个会话运行器，以及它们下面的间隔重复调度。测验是作答真正到达 [`learning-progress.md`](learning-progress.md) 的地方；在 M3.2 之前，调度器已经存在，却没有任何东西调用它。

## 各种模式

| 内容库 | 模式 | 显示 | 作答方式 |
|---|---|---|---|
| 单词 | 日语 → 词义 | 单词 | 四选一 |
| | 词义 → 日语 | 词义 | 四选一 |
| | 读音 → 写法 | 读音 | 四选一 |
| | 写法 → 读音 | 单词 | 四选一 |
| | 听力 | 什么都不显示——它被朗读出来 | 四选一 |
| | 输入读音 | 单词 | 键入 |
| 假名 | 假名 → 罗马字 | 假名 | 四选一 |
| | 罗马字 → 假名 | 罗马字 | 四选一 |
| | 听力 | 什么都不显示——它被朗读出来 | 四选一 |
| 语法 | 填助词 | 带空格的句子 | 四选一 |
| | 选活用形 | 带空格的句子 | 四选一 |
| | 排序 | 译文 | 点击片段排序 |
| | 选语法点 | 句子 | 四选一 |

每一项在**设置 › 学习 › 测验模式**里都有一个开关。最后一个开关关不掉：没有任何模式的测验打开就是空的，看起来像坏了而不像被配置过。

## 题目要么生成得出来，要么就没有

`QuestionGenerator` 返回 null 的次数远多于返回题目，这是设计而不是失败。大多数词没有汉字，因此两种写法模式对它们不适用；大多数词没有例句；处在条目稀少级别的词可能凑不出三个像样的干扰项。生成器不会先挑好模式再去碰运气，而是按打乱后的顺序逐个尝试已启用的模式，第一个能出题的胜出。

有四样东西是被直接丢弃而不是凑合的：

- **没有日语语音的设备上的听力模式。** 听不到的题目没有答案，因此 `QuizPage` 在生成任何题目之前就把它们移除。
- **没有句子分析器时的语法模式。** 四种里有三种需要解析好的例句。只有当这类模式被启用时才会去 await 分析器，因为在 7,700 个词条上构建词典要花几十毫秒，而假名测验根本用不上它。
- **日语界面下基于译文的语法模式。** 对照含义排列片段，以及在句子与含义之间双向匹配，都以目录例句的英文或中文译文为素材，而日语读者看不到日语的译文。`translationQuizModes` 列出了它们；测验页丢弃它们，测验模式页把它们的开关显示为关闭并附上原因。
- **选项不是四个互不相同字符串的任何题目。** 这是选择题组装前的最后一道检查：两个相同的选项意味着两个正确答案，而任何单一的干扰项规则都无法对所有模式独自排除这一点。

## 干扰项

错误选项有两种失败方式。明显的一种是碰巧也正确——同义词，或者じ和ぢ都作为「ji」出现。隐蔽的一种是太容易：一堆动词里的一个名词，或者一堆两个假名的词里的一个三字汉字复合词，仅凭外形就能排除，题目也就什么都没测到。

- **词义。** 同级别、同词性，常用词优先；只有在凑不满四个时才依次放宽到同级别、再到整个内容库。与答案共享任何一个义项的词直接排除。
- **写法。** 同级别，优先选择共享某个字或读音长度相同的词。同音词被排除，否则读音题会有两个答案。
- **假名。** 先用内容库自带的 `confusableWith` 列表——シ与ツ、ソ与ン、ぬ与め——因为那才是学习者真正可能犯的错。其次是同一行，最后才是任意。**按罗马字去重**，这正是防止じ和ぢ同时出现的机制。
- **助词。** 取自 N5 学习者会遇到的十五个助词的固定列表，而不是整张功能词表：把冷僻助词作为错误选项，不是任何人会犯的错误，反而泄露了答案。
- **活用形。** 同一个词的其他真实形式，由 `Conjugator` 写出。每个选项都是日语，而只有一个适合该句。
- **语法点。** 同级别、且**自身形式没有出现在该句中**的语法点。没有这道检查，一个以です结尾的句子就会把〜です作为错误选项提供给一道关于句中别的东西的题目。

## 正向活用

分析器一直只做反向的去活用，因为解析需要的是那个方向。测验需要另一个方向，因此 `Conjugator` 从辞书形和活用类别写出敬体、否定、过去与て形。两个方向共享 `godan_rows.dart` 里的行表，因此测验绝不会拿一张与解析器不一致的表来判分。

它刻意不是一个通用引擎：只有四种形式，其余一律返回 null。一个不是该词真实形式的干扰项会教错东西，而一道没有正确答案的题更糟。

**一个活用形是好几个 token。** 分析器把食べます拆成携带已恢复ます形词干的食べ，以及作为独立助动词的ます——正是这种拆分让解析可行。因此活用题会跨越动词 token 加上其后附着的每个助动词，并且在活用器无法精确重现句子所写内容时跳过该题。

## 判分

- **选择题**按下标判分。
- **输入读音**接受假名或罗马字：用日语键盘的学习者产出前者，没有输入法的产出后者，两者都不算错。会先用 `toHiragana` 折叠片假名、长音和全角字符。**不**被折叠的是不同的读音——が和か是不同的词。
- **排序题**在所选位置递增时判为正确，之后显示的期望答案是各片段拼接起来，也就是那个句子。

## 一次会话

`QuizSession` 只掌管队列和成绩，别无其他。写入进度是一个回调而不是依赖，因此该文件不 import 任何存储，测试也能精确观察它本会写入什么。

- **每个条目只记录第一次作答。** SM-2 评的是回忆的好坏；一分钟内第三次才答对的条目并没有被回忆起来。
- **答错的条目会在本次会话里再回来**，排到队尾，最多两次。这种重复正是学习发生的地方，而上限则防止一个难缠的条目让会话永远结束不了。
- **答错之后总是显示正确答案。** 没被告知答案就重新排队的条目，只会被再猜一次而不是学会。
- **成绩按首次作答正确率计**，总结里通过内容库指名答错的条目，而不是列出 id。

作答是发生时就记录而不是结束时统一写入，因此中途被系统杀掉的应用仍保留已答的部分。同步调度器有防抖，所以多出来的保存不会变成多出来的上传。

### 会话进行中才到达的题

`QuizSession.append` 把一道题加进正在进行的会话并把总数加一，这样进度行仍然诚实。有两处用到它，且都是可选的额外内容：单元会话在已经显示之后向设备端模型索取最多三道题（见 [`ai-assist.md`](ai-assist.md)），这样来的题都带 `generated`。

**生成的题永远不会调用 `onFirstAnswer`。** 它可能是错的，而一道错题不能被允许改动真实的复习间隔——见 [`learning-progress.md`](learning-progress.md)。它还会在题面上方带标注，在读题之前就显示。

### 是什么在引出一道题

运行器会在题面上方写一行，它按顺序来自三个地方：题目自带的 `instruction`（如果有），JLPT 题目就是这样带着自己那个大問的措辞的；题目带 `authored` 时则什么都不写，因为单元文件里的题本来就是按人问问题的方式写的，在「哪一句是礼貌的说法？」上面再加一行只会引出另一个问题；除此之外，用所属题型自己的那句话。

单元里自己编写的题和生成的题，不管实际问的是什么，一律归在 `QuizMode.grammarPattern` 之下，所以题型对这两者都不可信。生成的题是填空题，因此用填空那句话，并在它上面写出这道题被要求考的语法点及其意思——那是题目的前提，不是题目的答案。而在自己编写的语法点题里，语法点**就是**答案，所以事前绝不点明。任何语法题答完之后，都有一个纸片按钮通向这个语法点自己的页面。

### 带有自己 id 的题目

上面说的一切都按**条目**计分，在题目由应用自己想出来的时候这是对的：关于同一个语法点的两道生成的题，就是同一道题问了两遍。

JLPT 练习题不一样。一份卷子会围绕同一个词问好几道真正不同的题，所以练习题带一个 `questionId` 并按它计分；若按条目计分，关于 会う 的第二道和第三道题就永远不会被计入。调度仍然只被告知每个条目一次，取的是问到它的第一道题。

还可以告诉会话**不要重新排队**（`requeue: false`），计时的卷子就是这么做的——一份长度取决于做得好不好的卷子，没法按固定的题目构成来计分——并且可以让它**弃考**，把剩下的题记为 `answered: false` 而不是记为答错。见 [`jlpt-practice.md`](jlpt-practice.md)。

那次改动带出了两个潜伏的 bug，两个都早就躺在生成题的路径上没被发现，因为此前从没有哪次会话会连着问同一个条目的两道题：作答控件以条目与模式为键，于是第一道题的选择被带进了第二道；而是否重新朗读的判断比较的也是同一对值，于是第二道题变哑了。现在两处比较的都是题目本身。

## 测验从哪里开始

| 入口 | 出题范围 |
|---|---|
| 学习 › 今日 › 开始复习 | 所有到期项，逾期最久优先 |
| 学习 › 今日 › 学习新内容 | 今日的新条目额度 |
| 假名表 › 测验操作 | 全部行，使用当前显示的字体 |
| 单词 › 测验操作 | 列表当前筛选的级别 |
| 语法 › 测验操作 | 列表当前筛选的级别 |

`/quiz` 是标签页外壳之外的一条路由，用 `context.push` 进入，并以 `QuizConfig` 作为它的 `extra`——与句子实验室形状相同，理由也相同：它是带着目的进入、做完就离开的东西，而不是一个可供浏览的地方。中途离开会先询问，但仅在已经答过题的情况下。

## 题面里的读音

只要读音不是被考的对象，题面就带振假名。日语 → 词义会把读音印在词的上方；选语法点会用句子自带的读音；填空题会把读音在同一区间挖空，否则句子上方的假名就把答案说了出来。

**写法 → 读音与输入读音永远不带**，作答前的听力题也不带。把答案印在题面上方不是一种排版选择。

读音无法对齐时——见 [`../algorithms/furigana-alignment.md`](../algorithms/furigana-alignment.md)——题面退回测验原先使用的副标题行，因此两种情况下读音都恰好显示一次。

## 布局

当 `canSplitLayout` 判定窗口形状合适时，题目面板固定在左侧、作答区在右侧；否则堆叠。规则及其代价见 [`../adaptive-layout.md`](../adaptive-layout.md)。

## 用键盘作答 <a id="from-a-keyboard"></a>

坐在键盘前的学习者不用鼠标就能答完整个会话。这些按键属于 `QuizRunner`，因此练习测验、单元会话、检查点和模拟试卷都有它们。

| 按键 | 作用 | 仅在此时 |
|---|---|---|
| `1`–`9` | 选择题：选中第 *n* 个选项。排序题：放入剩余片段中的第 *n* 个 | 不在输入题上，那里的数字是文本 |
| `Backspace` | 把最后放入的片段取回 | 排序题，且已放入了片段 |
| `Enter` | 检查，然后继续——就是那个实心按钮 | 已组好答案，或答案已提交。在未作答的输入题上，Enter 归输入框，由它提交 |
| `R` | 重播题目的音频 | 题目有音频，且存在日语语音 |
| `S` | 跳过一道生成的题目 | 是生成的题目，且尚未作答 |
| `Esc` | 离开，经过与返回按钮相同的确认 | 不变 |

在桌面上，选项和剩余片段带着各自的数字，检查按钮下方有一行文字列出这些按键。手机两样都不显示；接了键盘的平板仍然能用这些按键，只是不会被告知。数字会随着片段的放入而变化，按键跟随屏幕上的数字。

**按键只在其操作存在时才存在。** 被快捷键匹配到的按键总是会被消耗，所以如果在输入题上绑定了数字，它就永远到不了输入框。因此运行器按题目、按状态构建绑定，而不是先全部绑定再忽略其中一部分。焦点遵循同样的规则：每次换题之后，测验自己的按键处理器取得焦点；只有未作答的输入题例外，由输入框取得焦点，这样可以立刻打字。

在会话前后，键盘用户接下来要按的那个按钮已经持有焦点：模拟试卷开始卡片上的「开始」，总结页和试卷结果页上的「完成」，以及两个离开对话框里的**「取消」**，这样出于习惯按下的 Enter 永远不会让人走出一份计时试卷。

场景分支选择、书写练习和各个标签页还没有快捷键。
