# 句子实验室

输入一个日语句子，看看它由什么组成：有哪些词、什么修饰什么、用到了哪些已收录的语法点，以及有什么看起来不寻常。分析是确定性且离线的——一部词典加一组规则，不是翻译器，也不是模型。算法的推导见 [`../algorithms/sentence-analysis.md`](../algorithms/sentence-analysis.md)；本页描述这个功能。

## 它在哪里

一个位于 `/lab` 的全屏路由，在导航外壳**之外**。五个标签页是本应用围绕其构建的参考资料；实验室是你对已有句子*施加*的动作，第六个标签会为一个总是带着目的进入的页面挤占底栏。

有四个入口：

| 来自 | 方式 |
|---|---|
| 学习 | 快速开始链接，以 push 方式进入，返回键回到仪表盘 |
| 词汇、语法 | 应用栏上的操作 |
| 两个详情表中的任意例句 | 该行溢出菜单中的**分析这个句子** |
| 它自己 | 在输入框里键入 |

从详情表打开的例句作为路由的 `extra` 传入，到达时即分析。传过去的是**书写形式**的句子，而不是它的假名读音：分析器读得懂汉字，而大多数词边界正是靠汉字才看得见。

## 它显示什么

四个部分，依次排列，每一部分都引用它上面的那一部分。正是这条链条决定了这些部分在任何窗口尺寸下都是单列——把引用和被引用并排放置会让阅读顺序变得含混。在宽到可以分栏的窗口上，*输入*会移到它们旁边自己的一栏里，这不改变那条链。已记入 [`../adaptive-layout.md`](../adaptive-layout.md)。

写作练习通过同一个部件显示同样的四个部分，每句一份。在一个页面上学会怎么读，在另一个页面上读到的就是同一份答案；见 [`writing-practice.md`](writing-practice.md)。

### 词

句子被呈现为一排色块，每个词一个，超出时换行而不是横向滚动——一眼看到整句正是重点所在。每个色块显示书写形式的词、从中还原出的语法形式（`masuStem + polite + past`），以及它是哪一类词。

颜色按类别对色块分组，而**每个色块下方的标签用文字点明该组**，因此颜色从不是含义的唯一载体。六个名称刻意覆盖二十个内部类别：学习者想知道某个词是助词，而不是想知道它是提示助词而非接续助词。

点击色块会为目录词打开词汇详情表——与词汇页打开的是同一个表，因此在这里查到的词与在那里查到的是同一个页面。功能词没有目录条目，因为它属于语法而非词汇，所以显示它自己的释义。

任何词典中都没有的词以错误色绘制并标注出来，各部分上方还会有一条提示，说明分析中的某些部分可能不对。被告知哪一部分不可靠，比一个看起来干净的答案更有价值。

### 结构

每个文节一行，按句子顺序排列，各自注明它依附于什么；最后一行写着*主谓语*。按句子顺序而不是树的顺序，因为学习者正在读自己刚写下的句子，重排会让找到某一行的难度超过这一关系本身的价值。

依存关系是一个**猜测**——标准的右侧中心规则，且不建模小句边界。页面结尾的说明会讲明这一点。

### 用到的语法

句子用到的每个已收录语法点，附上匹配的片段，点击打开与语法页相同的详情表。什么都没匹配到时会明确说明，而不是什么也不渲染：没有用到任何已收录句型的学习者应当得到这个答案，而不是一处需要自行解读的空白。

### 可能的问题

五项检查，每一项都写成在不确定时保持沉默——豁免条件列在算法页中。每一行引用它所针对的句子片段，并用一句话说明哪里看起来不寻常，语气是"可能"。最多显示三条：触发更多的句子更可能是分词出错，而不是真的错那么多。

## 历史记录

每个分析过的句子都会被记住，最新的在前；点一下就把它放回输入框并重新分析。窗口够宽时列表在输入区下方，窄时在顶栏按钮后面。

**只保存句子本身**——不保存分析，它会从文本和随应用发布的目录重新算出来；也不保存模型生成的任何内容。保存分析等于把一个下个版本会改进的答案冻结起来；保存生成文字等于留着一个错误答案供人再读一遍。

条目是进度文件里的 `lab:<hash>` 记录，因此和其他一切一同同步，冲突时也和普通记录一样进到冲突对话框。它的 id **由句子本身推导而来**，这正是同一个句子分析两次只会更新一条、而不是新增一条的原因，也是两台设备分析了同一句话会合并成一条的原因。每个页面各保留一百条，超出的从最旧的丢弃。删除是真正的删除，合并会把它传播出去。格式见 [`../data-formats.md`](../data-formats.md)。

## 功能词表

`assets/content/function_words.json`——大约九十个助词、系动词各形、助动词和形式名词，每个都带 `fw:` id、英文与中文释义、它所接的词干形态，以及它贡献的语法形式。id 与目录 id 一样，是兼容性约定。

对同一表层而言，该表**优先于词汇表**：は 是提示助词的时候远多于它是 歯，把两者等量齐观的分析器在大多数句子里都会出错。它还携带各项检查所读的命名词集——`time-past`、`time-future`、`path-verbs`、`transitivity-pairs`。

它与目录分开加载，因为它只有几 KB，而且只有本页需要它；把它与 2 MB 的目录一起加载会让每个页面为一个可能永远不会打开的页面付出代价。

## 页面中写明的限制

- 它是一部词典加一组规则，不是翻译器。
- 结构是最佳猜测。
- "可能的问题"值得核对，而不宜直接采信。
- 内置词典缺少的词会在出现之处被指出。

## 可选的端侧模型

`PLAN.md` M2.4 用 Android AICore 填上了 `SentenceEnhancer` 这个接缝，它是一项可选增强，永远不会成为事实来源。在**设置 › 端侧 AI** 中打开后——在此之前一直关闭——每条可能的问题旁会多出**解释**按钮，其下会出现**解释这个句子**与**给出改写建议**。它产出的一切都画在带「生成」标注的卡片里，位于它所评论的那条确定性发现之下，且不会被保存——历史记录里也不会。

每个按钮各自由它用到的那项功能决定：解释用 Prompt API，改写用校对 API。只有其中一项的设备会拿到能用的那一半。

开关关闭时，或在 Android 以外的任何平台上，本页就是本文其余部分所描述的样子。见 [`ai-assist.md`](ai-assist.md)。
