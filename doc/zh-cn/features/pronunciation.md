# 发音

应用中一切发声与听声的部分。对应 `PLAN.md` 的第二阶段。所有工作都由设备自身的语音引擎完成：**录下的、输入的、说出的内容都不会离开设备。**

## 语音合成

通过 `flutter_tts` 调用平台引擎——Android 的 `TextToSpeech`、Apple 的 `AVSpeechSynthesizer`、Windows 语音平台。应用只掌管三项引擎状态：语言（始终是 `ja-JP`）、朗读速度和所选语音。

### 哪些内容会被朗读

| 位置 | 按钮 | 朗读的文本 |
|---|---|---|
| 词汇详情表 | 等级标签旁 | 词条的假名 `reading` |
| 假名详情表 | 罗马字旁 | 平假名 |
| 假名表格子与搜索结果 | **长按**，无按钮 | 当前显示字体下的该假名 |
| 两个详情表中的每个例句 | 行尾 | 句子的假名 `reading`，缺失时回退到表层文本 |

**始终优先使用假名读音而非汉字表层。** 引擎拿到「一日」必须在 ついたち 和 いちにち 之间猜；拿到 ついたち 则无需猜测。每个词条都带读音，每个语法例句也带，因此回退到表层的情况很少。

### 一个声音，一段朗读

`TtsService.speaking` 是单个 `ValueNotifier<String?>`，保存当前正在播放的文本。每个按钮都监听它，因此正在播放的那个显示停止图标，其余保持静止。点击正在播放的按钮会停止；点击另一个则打断并开始新的朗读。设备上只有一个声音，UI 绝不暗示相反的事。

### 速度与语音

设置 → 语音。速度滑块在 0.6× 到 1.2× 之间以 0.1 为步进，配有试听按钮朗读一句固定的问候语；语音下拉框列出已安装的日语语音（引擎提供少于两个时该行隐藏）。两者都是 `storage_config.json` 中的设备本地偏好（`ttsRate`、`ttsVoice`）：手机扬声器和桌面扬声器需要不同的速度，而语音名称在另一台设备的引擎上毫无意义。

`flutter_tts` 在其支持的**每个平台上都把 0.5 视为正常速度**，因此 `TtsService.engineRate` 把用户面的数值乘以 0.5，这里没有平台分支。若某个语音名称不再存在——两次运行之间被卸载——则回退到引擎默认语音，而不是失败。

### 没有日语语音时

这很常见，且不是错误：全新安装的 Windows 一个都没有，Android 设备的引擎也可能缺少日语数据。此时

- 每个朗读按钮**被禁用而非隐藏**，原因写在工具提示里——消失的按钮会让人以为功能不存在，而这是用户可以自行修复的设备状态；
- 设置 → 语音把速度和语音两行换成一段说明，并在 Android（通过应用唯一的方法通道发出 `com.android.settings.TTS_SETTINGS` intent）和 Windows（`ms-settings:speech`）上提供一个打开系统语音设置的按钮。Apple 平台没有有文档的深链接，因此文案改为指出设置面板的位置。

Android 11+ 的软件包可见性要求清单中声明 `android.intent.action.TTS_SERVICE` 查询，否则引擎不可见，应用会报告没有任何语音。
