# 发音

应用中一切发声与听声的部分。对应 `PLAN.md` 的第二阶段。所有工作都由设备自身的语音引擎完成：**录下的、输入的、说出的内容都不会离开设备。**

## 语音合成

通过 `flutter_tts` 调用平台引擎——Android 的 `TextToSpeech`、Apple 的 `AVSpeechSynthesizer`、Windows 语音平台。应用只掌管三项引擎状态：语言（始终是 `ja-JP`）、朗读速度和所选语音。

### 哪些内容会被朗读

| 位置 | 按钮 | 朗读的文本 |
|---|---|---|
| 词汇详情表 | 等级标签旁 | 词条的假名 `reading` |
| 假名详情表 | 罗马字旁 | 平假名 |
| 假名表格子与搜索结果 | **长按**，无按钮 | 当前显示字体下的该假名 |
| 两个详情表中的每个例句 | 行尾 | 句子的假名 `reading`，缺失时回退到表层文本 |

**始终优先使用假名读音而非汉字表层。** 引擎拿到「一日」必须在 ついたち 和 いちにち 之间猜；拿到 ついたち 则无需猜测。每个词条都带读音，每个语法例句也带，因此回退到表层的情况很少。

### 一个声音，一段朗读

`TtsService.speaking` 是单个 `ValueNotifier<String?>`，保存当前正在播放的文本。每个按钮都监听它，因此正在播放的那个显示停止图标，其余保持静止。点击正在播放的按钮会停止；点击另一个则打断并开始新的朗读。设备上只有一个声音，UI 绝不暗示相反的事。

### 让引擎保持在日语

这个功能最难的部分不是选语音，而是 **Android 引擎不会保留你给它的语言**，而且丢掉时什么都不说。`flutter_tts` 的插件会在两个地方把语言覆盖成系统默认：

1. **在它自己初始化之后。** 平台引擎启动期间，插件会把方法调用排队；它的 init 回调重放这些调用，*然后*把语言设成系统默认语音的区域设置。在此之前发出的 `setLanguage('ja-JP')` 会被应用，然后立刻被丢弃。
2. **在一次静默重建之后。** 当引擎的服务连接断开——应用在后台待过一段时间后这很常见——下一次 `speak` 会重建 `TextToSpeech` 实例、把这次朗读重新排队，并在一个回到系统默认语言的全新引擎上把它读出来。

这两件事从 Dart 侧都看不见：`isLanguageAvailable` 和语音列表照样报告有日语，于是应用以为一切正常，而引擎正把假名当英文读。表现出来就是单词发音不对而语法例句正常——差别只在于先打开了哪个页面——并且进一次设置就恢复，因为在那里选语音会显式设定一个。

三件事修复了它，都在 `TtsService` 里：

- **第一次写入之前先做一次探测。** `init` 会 await 一次 `isLanguageAvailable` 并丢弃结果。换成任何一个会被排队的调用都可以；关键在于 await 到它就意味着插件的覆盖已经发生，其后的 `setLanguage` 才留得住。
- **每次朗读前重新应用。** `speak` 每次都重新设定语言、语音和语速。三次引擎调用只花几毫秒，而且没有别的事件可以监听。
- **选定语音，而不只是语言。** 应用总是指名一个具体的日语语音——设置里选的那个，或可用的最佳者——这样引擎就无法退回到它上次停留的语音上。

如果语言仍被拒绝，而本次运行中它曾经可用，`speak` 会通过 `setEngine` 重建一次引擎并重新应用全部设置。从未有过日语的设备不会为此付出代价。

### 速度、语音与引擎

设置 → 语音。速度滑块在 0.6× 到 1.2× 之间以 0.1 为步进，配有试听按钮朗读一句固定的问候语。

**日语语音**一行会打开一个选择面板，仅当引擎提供多于一个日语语音时显示。引擎的语音名称是标识符——`ja-jp-x-jab#male_1-local`——既说不出这个声音是什么样，在别的引擎上也不一样，所以面板改为给它们编号：「日语语音 1、2、3」，排序规则是已安装优先于缺失、离线优先于联网、再按引擎自称的音质、最后按名称，使顺序完全确定、编号不会在两次运行之间移动。每一行说明这个语音有什么不同，用小字显示原始名称以便反馈问题，并带一个播放按钮。**试听不等于选择：** 样例通过 `TtsService.preview` 播放，它在 `finally` 中恢复学习者自己的语音。

**语音引擎**一行仅当设备装有多个引擎时出现，这在 Android 上很常见——Google 的引擎和厂商的引擎，两者语音并不相同。已知引擎显示品牌名；其余显示包名，那同样是事实。切换引擎会重建平台引擎并丢弃已选语音，因为一个引擎的语音名称在另一个引擎上什么都不指。

三者都是 `storage_config.json` 中的设备本地偏好（`ttsRate`、`ttsVoice`、`ttsEngine`）：手机扬声器和桌面扬声器需要不同的速度，而语音名称与引擎包名在另一台设备上都毫无意义。

`flutter_tts` 在其支持的**每个平台上都把 0.5 视为正常速度**，因此 `TtsService.engineRate` 把用户面的数值乘以 0.5，这里没有平台分支。若某个语音名称不再存在——被卸载，或引擎已切换——则回退到可用的最佳日语语音，而不是引擎默认语音，因为后者未必是日语。

### 没有日语语音时

这很常见，且不是错误：全新安装的 Windows 一个都没有，Android 设备的引擎也可能缺少日语数据。此时

- 每个朗读按钮**被禁用而非隐藏**，原因写在工具提示里——消失的按钮会让人以为功能不存在，而这是用户可以自行修复的设备状态；
- 设置 → 语音把速度、语音和引擎三行换成一段说明，并在 Android（通过应用唯一的方法通道发出 `com.android.settings.TTS_SETTINGS` intent）和 Windows（`ms-settings:speech`）上提供一个打开系统语音设置的按钮。Apple 平台没有有文档的深链接，因此文案改为指出设置面板的位置。

Android 11+ 的软件包可见性要求清单中声明 `android.intent.action.TTS_SERVICE` 查询，否则引擎不可见，应用会报告没有任何语音。

## 语音识别

通过 `speech_to_text` 调用平台识别器——Android 的 `SpeechRecognizer`、Apple 的 `SFSpeechRecognizer`、Windows 语音平台。插件背后没有 Linux 实现，因此 `platformMayRecognizeSpeech` 会在任何人索要麦克风之前就在那里拒绝。

### 默认在端侧

除非学习者打开**设置 › 语音 › 允许网络识别**，否则每次聆听请求都以 `onDevice: true` 发出。在 Android 上这对应 `EXTRA_PREFER_OFFLINE`，即**只用离线**：在没有下载日语模型的设备上，请求会失败，而不是悄悄发往服务器。该失败被报告为 `languageUnavailable`，练习表把它转成一条同时给出两种修复方式的提示——安装日语语音数据，或者在知情的前提下打开回退。

除 WebDAV 同步之外，这个开关是应用中唯一会让内容离开设备的设置，它的副标题也正是这样写的。它默认关闭并以缺失键的形式存储（`speechNetworkFallback`），因此从未碰过它的设备永远不会把音频发往任何地方。

### 麦克风

`RECORD_AUDIO` 在清单中声明，但在**首次使用**时才申请，绝不在安装时申请：当权限尚未授予时，练习表会在第一次 `initialize()` 之前先弹出自己的说明对话框，因此系统弹窗绝不会毫无解释地出现。

在真机上试过之前，这个承诺有一个漏洞。设置 → 语音在页面构建时就去问识别器是否可用，而「问」意味着 `initialize()`，正是它触发系统弹窗——于是**仅仅打开设置页就会凭空冒出一个麦克风授权对话框**。现在它先检查权限，只有在已授予时才初始化；未授予时状态行会说这项检查在你首次练习时才进行，这是事实，而且与「本设备没有识别器」不是同一个判断。`test/speech_settings_tiles_test.dart` 守住这一点：权限缺失时后端绝不会被初始化。iOS 和 macOS 带有 `NSMicrophoneUsageDescription` 与 `NSSpeechRecognitionUsageDescription`；macOS 沙盒需要在两个 entitlement 文件中都有 `com.apple.security.device.audio-input`。Android 11+ 的软件包可见性需要 `android.speech.RecognitionService` 查询，与语音合成那条并列。

不会把音频录成文件，也不会保存任何内容。识别器给出的文本用完即弃，练习表关闭时就被遗忘。

### 练习表

从词汇与假名详情表上的麦克风按钮进入，也可从每个例句行的溢出菜单里的**练习**进入。在任何窗口尺寸下都是单列；它包含带朗读按钮的目标行、一个录音按钮、音拍色块和图例。

| 状态 | 显示内容 |
|---|---|
| 空闲 | "点击开始朗读" |
| 聆听中 | 停止按钮，以及实时的部分转写 |
| 处理中 | 识别器定稿期间按钮禁用 |
| 完成 | 音拍差异，然后是分数，然后是听到的内容 |
| 失败 | 一句话说明原因和该怎么办 |

**差异是主要输出**，分数只是同一对齐结果的摘要；完美的尝试显示的是一句话而不是"100 / 100"。颜色从不单独承载含义——图例列出全部四种状态，缺失的音拍带删除线，替换会同时显示词条的读音和听到的内容。算法见 [`../algorithms/pronunciation-scoring.md`](../algorithms/pronunciation-scoring.md)。

练习表明确说明：它判断的是你是否**能被听懂**，而不是口音或声调。
