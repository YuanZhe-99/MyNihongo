# 端侧 AI 辅助

句子实验室之上的一个可选层：应用可以用更多文字解释它自己的一处发现、解释整个句子，并给出改写建议。它通过 Android AICore 在手机上运行，**在你打开它之前一直关闭**，并且绝不会改变它所评论的分析结果。

平台事实——AICore 是什么、有哪些 API、有什么要求、怎样检查一台设备——写在 [`../android-aicore.md`](../android-aicore.md)，那一页是写给本项目之外使用的。本页写的是 MyNihongo!!!!! 拿它做了什么。

## 策略

六条规则，每一条都由代码强制，而不是靠约定：

1. **默认关闭。** 在你打开设置里的开关之前，`storage_config.json` 中没有 `aiAssistEnabled` 这个键。从未碰过该设置的设备绝不会运行模型。
2. **开关是闸门，不是过滤器。** `AiAssistService` 在读取任何状态之前就拒绝每一个生成调用。开关关闭时，方法通道根本不会被触碰——这是 `test/ai_assist_service_test.dart` 的第一条断言。
3. **每次使用前都重新检查能力。** 系统可能在两次请求之间移除模型；记住的「就绪」会把这变成学习者无法理解的错误。
4. **生成的内容始终带标注。** 全部渲染在 `AiExplanationCard` 内，标注「在本设备上生成——可能有误」写在文字**上方**，而不是下方。
5. **生成的文字绝不替代确定性结果。** 卡片画在它所针对的那条发现之下。生成的内容不会被保存、同步、备份，也不会写入目录——更换句子或离开页面时它就消失了。
6. **绝不代替你去请求任何东西。** 唯一的网络活动是模型下载，由 AICore 系统服务而非应用执行，且只在你点击设置里的**下载**时开始。

## 它能做什么

| 操作 | 位置 | API | 没有它时 |
|---|---|---|---|
| 对某个可能的问题点**解释** | 每条问题行旁 | Prompt | 那条始终显示的确定性单句说明 |
| **解释这个句子** | 问题列表下方 | Prompt | 始终显示的「词」「结构」「用到的语法」三节 |
| **给出改写建议** | 问题列表下方 | 校对 | 无；检查已经说明了哪里看起来不寻常 |
| **为什么这样不对** | 测验答错处下方 | Prompt | 目录自带的语法说明，或该题自己的说明——它始终先显示 |
| **更多例句** | 词条详情 sheet 里 | Prompt | 目录自带的例句，而大多数词并没有 |
| **对键入答案的第二意见** | 点「检查」之后，且字符串比对判为不对时 | Prompt | 仅字符串比对，也就是此前的判法 |
| **改写你写的内容** | 写作练习中 | Prompt；Prompt 不可用时用校对 | 分词结果：用了本单元哪些词、每句怎么理解、哪里看起来不寻常 |
| **额外出一道题** | 单元练习会话中，带标注 | Prompt | 题池本身，它本来就够撑起一整次会话 |

最后一列的每一行才是重点：**兜底方案就是应用本身**。去掉 AI 只是去掉三个按钮，而不是去掉学习者依赖的功能。

## 模型被问了什么

`PromptBuilder` 用确定性流水线已经产出的东西拼装提示词：

- 归一化后的句子，
- 分词结果，连同活用还原得到的形态，
- 对于某个问题点，**与屏幕上一字不差**的那句说明，
- 目录自身对最多三个匹配语法点的说明，每段摘录都有长度上限，
- 要求：用界面语言回答、最多四句、措辞留有余地、**不要与上面的说明相矛盾**、不要加标题或问候语。

把应用自己的教学文字交给模型并禁止其相矛盾，是让解释与语法页对同一语法点的说法保持一致的办法。就学习者正在读的那句问题说明发问——而不是另行推导一句——则避免了回答一个他们看不见的问题。

提示词位于 `assets/content/prompts/sentence_explain.json`，像其他内容资产一样带版本号，含 `en`、`zh` 与 `zh_TW` 三套指令块，各项上限也作为数据存放。它们刻意不放进 ARB 文件：那里的内容永远不会被渲染。指令块按内容使用的同一套回退顺序选取，因此繁体中文读者得到的是要求繁体作答的提示词，交给模型的语法说明也是繁体的——用一种字体提问却用另一种字体做依据，等于让模型去翻译，而那不是它被要求做的事。**繁体中文的指令块尚未在设备上验证：**如果模型不理会它，回答会是简体中文，也就是这一块存在之前的样子。

## 回来的东西

`ResponseParser` 决定一个回答是否值得展示。它会去掉代码围栏、标题、项目符号、编号和行内强调；合并空行；在句子边界处截断；并对两种会教出错误东西的情况返回 **null**：

- 只是把提示词复述一遍的回答——复述的模型并没有回答；
- 与学习者所写在忽略空白后完全相同的「改写」——把它端出来等于说一个正确的句子写错了。此时界面会说模型没有给出不同的写法。

## 设置

**设置 › 端侧 AI**，仅在 Android 上显示——其他平台整节省略，因为每行都写着「不支持」的一节只是噪音。

开关带有一段平实的说明文字。其下每项功能一行（解释、改写建议），各有自己的状态；当系统说模型可以获取时，各有自己的**下载**按钮和进度。进度以 MB 而非百分比显示，因为系统并不总会报告总量，而一个中途必须消失的百分比比一个只增不减的数字更糟。

按钮下方那句话说明了由谁、在何时执行下载。它不是脚注：正是这句话让打开开关成为一个知情的选择。

### 当某一行说功能不可用时

两项功能有**各自的设备列表**，而 Prompt API 的那份更窄，所以一台设备可能有其中一个模型而没有另一个。这正是这里按功能分行、而不是给出一个统一「AI」状态的原因，也是**每个按钮都只由它实际用到的那项功能来决定是否出现**的原因。

在 `v0.3.2` 之前，后半句并不成立：句子实验室里的改写按钮和写作练习里的那个，都会在解释不可用时一起隐藏。一台校对功能已就绪的 Galaxy Z Fold 8 因此完全看不到 AI，而设置里却正确地报告了其中一项功能可用。现在每个按钮各自跟随自己的功能出现。

`v0.3.2` 同时把 `genai-prompt` 升到了 `1.0.0-beta4`——这是 Prompt API 在 Gemini Nano v4 设备（Z Fold8 系列在内）上运行所必需的版本。更旧的客户端在那里会抛出 `FEATURE_NOT_FOUND`，读起来像设备不受支持，但它不是。来龙去脉见 [`../android-aicore.md`](../android-aicore.md)。

无法提供功能的那一行会说明发生的是两件不同事情中的哪一件：

| 行 | 含义 | 其下的诊断行 |
|---|---|---|
| 本设备不支持 | AICore 被问到并拒绝了 | 原始的 `FeatureStatus` 值 |
| 无法访问 AI 服务 | 调用本身失败了 | 异常类名与消息 |

诊断行刻意不翻译：它是用来在反馈中引用的标识符，不是给人读的说明。分区底部还有一行，写明已安装的 AICore 版本与设备型号，或者说明根本没有安装 AICore。

两种失败行都带一个**重新检查**按钮，因为可用性会在应用什么都不做的情况下发生变化：AICore 会在设备初始化或系统更新之后自行准备，有时还要重启一次。没有这个按钮，重新询问的唯一办法是把开关关掉再打开。

它的由来是一台装有 AICore 的 Galaxy Z Fold 8 的反馈：两行都显示「不可用」，而应用里没有任何东西能说清究竟是设备不在公布的列表上、服务版本过旧，还是调用抛了异常。完整的诊断流程写在 `doc/zh-cn/android-aicore.md`。

## 在句子实验室里

开关关闭时，实验室与此前完全一样——没有按钮，没有提示，什么都没有。

开关打开且模型就绪时，每条问题行多出**解释**，问题列表下方出现两个针对整句的操作。卡片渲染在确定性内容之下，一次一个（AICore 每个应用同时只服务一次推理），生成完成后可关闭。离开页面会取消正在进行的生成，模型不会为没人会读的答案继续工作。

开关打开但模型尚未下载时，这些操作被一行指向设置的提示取代。一个总是失败的按钮教给学习者的是不信任这个功能，而不是怎么修好它。在根本无法运行模型的设备上，连那行提示也没有——因为没有什么可修。

## 键入答案的判定

这是模型的输出唯一会抵达进度文件的地方，值得把方式说准确。

确定性检查先跑，并且**「正确」这个词归它所有**。只要答案与目录所写的一致——假名也好、罗马字也好——就不会询问任何模型，也没有任何模型能把它拿走。

只有在那次检查说「不对」时，只有对键入题，也只有在开关打开时，才会去问模型两者是否表达同一个意思。**「是」会提升判定；「否」什么也不改**，因为那个答案本来就是错的。回复若打太极、首行不是 SAME 或 DIFFERENT，会被解析器拒绝，答案仍然是错的。

于是模型只能把「错」变成「对」，永远不能反过来；而且学习者会被告知发生了哪一种：那句评语出现在判定下方，并冠以「端侧模型判为正确」。

这是对「生成的文本绝不写入进度记录」的一次有意例外，而它之所以安全，在于这种不对称。字符串比对的失败方式，是把正确的答案判错——那会让学习者觉得这个应用根本没在听。而这一条的失败方式，是偶尔宽容了一次。

## 轮流使用

设备上只有一个模型，`AiAssistService` 一次只允许一次生成，因此两个都想用它的功能必须排队。排队由 `AiPracticeService` 负责，规则是**学习者的请求优先**。

交互请求彼此排队，而不是以「忙」失败——连点两个按钮的人应该得到两个答案，而不是一个错误。后台任务会等待任何交互请求，在模型忙时重试几次，然后**安静地放弃**：没有谁在等它，也就没有谁需要被告知。

`AiPracticeService` 不 import 任何存储或进度 provider，并且有一条测试通过读取该文件自身的 import 列表来断言这一点。生成的内容不写入任何记录。

## 如何读回来的东西

每一个解析器都宁可拒绝，也不猜测。

- 没有 `Rewrite:` 行的写作回复整条丢弃。改写是学习者唯一能直接照做的部分。
- 首行不是 `SAME` 或 `DIFFERENT` 的判定回复丢弃，改由学习者自己判定——那本来就是没有模型的设备上会发生的事。
- 不是恰好三个以竖线分隔字段的例句行丢弃。生成的句子与目录自带的并排显示，否则它看起来会和有人写的一样权威。

一个无视格式的模型，其内容也同样不可信，所以半解析出来的答案比没有更糟。

## 明确说出的限制

- 模型很小。它有时会错，标注每次都会这么说。
- 输出语言由指令跟随界面语言，不是保证。
- 校对只接受短输入；过长的句子会被拒绝而不是截断，因为校对半句话等于对没人写过的句子提出修改建议。
- 冷启动后的首次推理很慢。有 45 秒超时，避免卡住的请求把加载指示永远留在屏幕上。
- 仅限 Android，且仅限 AICore 提供服务的设备。

## 已在设备上验证

与 Phase 2 的其余部分不同，这一部分是在真实硬件上核对过的：一台 **Pixel 10，Android 17**，2026-09-03。在 release 构建中实测了：

- 开关关闭——任何地方都没有 AI 相关内容，方法通道从未被调用；
- 开关打开——两项功能都报告了状态，两个模型都从设置中下载完成；
- **解释这个句子**、对某条问题点的**解释**、以及**给出改写建议**，三者都正确作答且使用界面语言，**英文与简体中文均已验证**；
- 校对一个正确的句子，它原样返回，被报告为「模型没有给出与原句不同的写法」而不是当作修改建议；
- 加载状态，以及生成期间其他操作被禁用。

一次回答约需 20–30 秒。同一次改动中还发现并修复了两个测试主机永远不可能暴露的缺陷：R8 把 ML Kit 压缩成了看起来像设备不受支持的失败，以及设置页一打开就弹出麦克风授权（见 [`pronunciation.md`](pronunciation.md)）。两者都记录在 [`../android-aicore.md`](../android-aicore.md)。

## 生成的题目

开关打开时，**单元练习会话**会向模型索取最多三道关于本单元语法点的额外题目。有四件事框住了它的代价：

- 会话先建好、先显示；生成在之后进行，走 `AiPracticeService.runInBackground`，它会给任何交互请求让路。**等待模型永远不会拖慢第一题。**
- 生成的题带 `QuizQuestion.generated`，因此回答它**永远不会进入 SM-2 调度器**。答对答错都不会改变复习间隔。
- 每个回复在变成题目之前都要检查：必须有挖空、四个互不相同且非空的选项、以及一个指向其中之一的 `Answer:`。其余一律静默丢弃。见 [`ai_question_generator.md`](../functions/features/quiz/services/ai_question_generator.md)。
- 题目的生成标注显示在**题面上方**，在读题之前，而不是答完之后。
