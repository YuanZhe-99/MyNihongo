# 用户看到的同步与备份

引擎本身见 [`../sync.md`](../sync.md) 与 [`../backup-restore.md`](../backup-restore.md)。本页描述界面。

全部位于**设置 › 数据**之下，使数据相关的一切集中在一处。窗口宽到可以分栏时，每一行在列表旁的详情窗格中打开；
窄窗口下则全屏推入。两者使用相同的控件 —— 见 [`../adaptive-layout.md`](../adaptive-layout.md)。

## WebDAV 同步

`lib/shared/views/webdav_config_page.dart`。该行的副标题是实时状态：待处理冲突优先于普通失败，失败优先于上次
成功；未配置服务器时显示“尚未连接”。页面本身：

1. Nextcloud 预设按钮填入地址形式与默认远程路径 `/MyNihongo`。
2. 服务器地址、用户名、密码与远程路径，然后是**保存**与**测试连接**。
3. 保存了包含服务器与凭据的配置后，其余部分才出现：状态卡片、同步进行时显示当前阶段的进度条、**立即同步**、
   **强制上传**、**强制下载**、自动同步开关与**断开连接**。

发现冲突的同步会为每条记录打开一个对话框，展示两个版本的修改时间、正确与错误次数、连续答对次数、阶段与上次
复习时间。关闭其中任何一个都会中止整次解决：不上传任何内容，冲突保持待处理。强制上传与强制下载都会先以错误
色请求确认，因为它们各自会丢弃一侧的更改。

## 备份

`lib/features/settings/views/backup_page.dart`。信息卡片说明备份包只留在本机。其下是自动备份开关、保留期限
下拉（永久、3、7、14、30、60、90 天）、**创建备份**，以及按时间倒序的历史记录。每行显示时间戳与大小；损坏的
备份包会被标注、无法还原，但仍可删除。

还原会先询问要从备份包中取出哪些模块，再确认。之后自动同步处于关闭状态，页面会说明这一点并提供强制上传 ——
自动合并一个还原后的旧文件，在其他设备上看起来会像大规模删除。

## ZIP 导出与导入

两行就地执行的操作。导出询问目录并写出 `mynihongo_export_<时间戳>.zip`。导入询问一个 `.zip`、确认，然后替换
本地进度。压缩包若含有应用数据文件以外的任何内容，会被整体拒绝，因此被篡改的压缩包绝不会被部分应用。

## 这些页面从不做的事

没有任何界面把内容发往用户自己的 WebDAV 服务器以外的地方。备份与导出只写到用户指定的位置。WebDAV 密码与兄弟
应用一样以明文存放在应用目录中；隐私政策对此有说明。
