# 参考页面偏好

应用按设备记住的五个小选择，让参考页面回到用户离开时的状态。它们与主题、语言一同保存在
`storage_config.json` 中；都不参与同步，因为手机和平板需要不同的列数，而习惯属于具体设备。

| 键 | 取值 | 默认 |
|---|---|---|
| `lastTab` | `learn`、`kana`、`vocab`、`grammar`、`settings` | 学习 |
| `vocabLevel` | JLPT 标签 | 全部等级 |
| `grammarLevel` | JLPT 标签 | 全部等级 |
| `kanaScript` | `katakana` | 平假名 |
| `referenceListColumns` | 1 到 4 | 自动 |

默认值会从文件中**移除**，而不是作为值写入。这既让文件保持精简，也让将来默认值的调整能覆盖到从未改过该设置
的设备。类型不对的值——文件是用户可指定目录中的纯 JSON，可以手工编辑——按“未设置”读取，而不是在启动时抛出
异常。

## 页面如何读取

`AppSettings` 承载全部五项，`appSettingsProvider` 在启动时加载一次。页面从 provider 同步读取，而不是各自发起
异步读取，因此在首次加载完成之前点选的筛选不会被它覆盖。`NihongoStorage` 拥有带类型的读写方法，notifier 拥有
内存中的状态。

## 上次所在的标签

`main()` 在 `runApp` **之前**读取 `lastTab`，并传给 `buildAppRouter(initialLocation:)`，因此应用直接在该标签
打开，而不是先显示“学习”再跳转。无法识别的值回退到“学习”。路由器只构建一次并保存在根组件的状态中：`GoRouter`
拥有导航历史，若在主题或语言变化时重建，会把用户在会话中途送回初始标签。

`ShellScaffold` 在每次切换标签时写入该键，写完即忘。因崩溃丢失这次写入，代价不过是下次从“学习”开始。

## 两个等级筛选

单词与语法有意保留各自的筛选：在读 N3 语法的学习者，往往仍在查 N5 的词。

## 列数

两个参考列表共用一个偏好，因为它们使用相同的卡片宽度与相同的规则；分成两个设置只会在无意中产生分歧。控件是每个
列表标题栏里的弹出菜单，在窗口只能容纳一列时隐藏而不是禁用——手机不该显示一个什么都做不到的菜单。

存储的是选择本身，而不是结果。`referenceColumnCount` 会把它钳制到实际放得下的列数，因此在平板上选的 4 在折叠
手机上渲染为 2，窗口变大后又回到 4。见 [`../adaptive-layout.md`](../adaptive-layout.md)。
