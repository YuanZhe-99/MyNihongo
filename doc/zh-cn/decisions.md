# 决策

路线图知道、而仓库里其他任何地方都没有记录的东西。MyNihongo!!!!! 是依照一份分阶段的计划
`PLAN.md` 构建的，从 2026-09-02 到 2026-09-24 分五个阶段。最后一个阶段发布时，这份计划
退役并被删除，本页保留了其中仍然有用的部分：工作所遵循的原则、里程碑索引（这样另一页或
源码注释里「M1.2」这样的引用仍然能解析）、带着每个选择理由的决策记录、刻意未构建的部分，
以及悬而未决的问题。

一次发布改动了什么，写在 [`version-history.md`](version-history.md) 里；本页说的是**为什么**。
从现在起发现的问题按 bug 报告并修复。下面日志记录的这类新决策，会在同一次改动里连同日期
一并加进来。

## 原则

1. **系列惯例优先。** 如果 MyAnime/MyDay/MyDevice 已经回答过某个问题（布局规则、同步不变量、
   文档结构、发布流程），就沿用那个答案。偏离之处会被写下来，并附上理由。
2. **内容即数据。** 内容目录文件是带 schema 版本号的、版本化的 JSON 资产，含每种语言的文本、
   JLPT 级别与稳定的 id。代码从不写死单词表。
3. **进度是唯一同步的用户数据**，一个模块（`nihongo_progress.json`），按记录三方合并，冲突
   呈现给用户。新的同步状态是一种新的记录种类或一个新模块——绝不是悄悄的后写者获胜。
4. **默认端侧运行。** 语音转文字、文字转语音和句子分析使用平台自带的引擎或随包算法。任何
   会把文字或音频发送出设备的功能都是可选开启的，并在隐私政策里披露。
5. **从第一天起就自适应。** 每个页面都通过 `adaptive_layout.dart` 决定自己的布局，在指定的
   折叠屏几何形状下测试过，并把它的判断记录在 [`adaptive-layout.md`](adaptive-layout.md) 里。
6. **平台中立的代码。** 平台分支只存在于 `platform_capabilities.dart` 里，读取
   `defaultTargetPlatform`；见 [`platform-notes.md`](platform-notes.md)。
7. **诚实的界面。** 没有构建的功能不会用假数据来充当，无法验证的东西会被标注为未验证。

**非目标。** 把汉字作为一等学习轨道（汉字通过词汇学习到达）。任何云端 AI、账号、遥测或广告：
除了到用户自己服务器的 WebDAV 同步，什么都不会离开设备。复刻官方 JLPT 历年真题：练习题内容
是原创的。

## 未构建

计划结束时刻意留下的部分，每一项的理由至今仍然成立。有人报告需要其中某一项时，按新的请求
处理。

- **自录回放**（M2.2）：录下学习者的尝试并回放。它需要与识别器同时使用麦克风，而没有设备
  无法验证，还会为 ARM64 构建再添两条原生 Windows 代码路径。没有其他东西依赖它。
- **在固定的折叠屏几何形状下渲染的截图**（M1.3）。流程和审查清单在 `tool/screenshots.md` 与
  [`adaptive-layout.md`](adaptive-layout.md) 里；拍摄需要实体手机。每个页面都在这些几何
  形状下由组件测试覆盖，以此代替。
- **只有硬件才能做的检查。** 日语界面和 `ja` 提示词块还没有在设备上读过，`zh_TW` 那一块也
  是；iOS 和 macOS 构建由 CI 编译，从未在 Apple 硬件上运行过；键盘快捷键还没有在实体键盘上
  试过。文档在每一处都保留着*未验证*这个词。
- **参考列表的方向键滚动。** 在桌面上方向键在条目之间移动焦点，与整个 Flutter 的行为一致；
  PageUp 与 PageDown 滚动列表（`0.5.3`）。
- **有人阅读模型撰写的内容。** 见第一个悬而未决的问题。

## 决策记录

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-09-02 | 一个同步模块 `nihongo_progress.json`，按 `modifiedAt` 逐记录合并 | 与 MyAnime 的单模块形状相同；这套引擎及其黄金测试文件已经在它上面得到验证 |
| 2026-09-02 | 记录种类由 id 前缀推导，不单独存储 | 没有什么会不同步；来自更新版本的未知前缀依然能加载并合并 |
| 2026-09-02 | 内容以 JSON 资产形式随包发布，不参与同步 | 这是应用的数据，不是用户的数据；同步它会让每台设备都携带两份内容目录 |
| 2026-09-02 | 假名数据从页面移到一个模型里 | 测验、TTS 和进度目录都需要它；MyAnime 把它放在页面内联，是因为只有那个页面用它 |
| 2026-09-02 | 门面沿用 MyAnime 的公开形状；没有 `sync_progress`/`sync_wake_lock` 这类垫片 | 兄弟应用里的垫片是为了本应用没有的历史包袱而存在的；页面直接 import `myapps_data` 的类型 |
| 2026-09-02 | ZIP 导入走严格模式（`rejectUnknownEntries`、`strictUtf8`、`validateBeforeWrite`、`atomicWrites`） | 没有已安装的旧版本需要为它保持宽松 |
| 2026-09-02 | 主题种子色 `FlexScheme.sakura` | 系列里每个应用都有自己的颜色；sakura 是这一个独一无二的标志 |
| 2026-09-02 | 第一阶段只做 Android | 语音 API 和折叠屏方面的工作只能在 Android 上验证；桌面平台只是一次 `flutter create` 之遥 |
| 2026-09-02 | 句子分析的基线是随包的经典流水线；AICore 是可选增强 | 确定性、可测试、在每台设备上都能用、没有隐私问题；AICore 的覆盖面还很薄 |
| 2026-09-02 | 第 3–4 阶段的 AICore 辅助练习（写作反馈、自由作答判分、解释、对话），但绝不设定分数或写入内容目录 | 有无 AICore 的设备之间结果保持可比；生成的文字始终带标注，且不进入随包发布的数据 |
| 2026-09-03 | 由进度 provider 而不是每个页面订阅 `AutoSyncService.addOnLocalDataChanged` | 每个页面共用一次订阅，而 riverpod 1.x 的 `ref.refresh` 会在每次后台同步时把一个已加载的页面清空 |
| 2026-09-03 | 备份页面不重新实现不变量 I5 | `myapps_data v1.0.1` 里的 `BackupEngine.restoreBackup` 已经在首次写入前禁用了自动同步——同一个配置文件的两个写入者会互相抢跑 |
| 2026-09-03 | `WebDavClient.download` 解码 UTF-8 字节而不是 `response.body`（包内修复） | 这里每一个进度 id 都含假名；`package:http` 在服务器不带字符集时会回退到 latin1，这会破坏每一条下载下来的记录。由黄金转写测试发现 |
| 2026-09-03 | 单词 id 是 `vocab:jm<JMdict 序号>`，种子 slug 保留为别名 | 序号是两个数据源共有的唯一稳定键；给 7,700 个词发明一个 slug 既做不到又会冲突 |
| 2026-09-03 | 三行 JLPT 词表在工具里被修正，而不是在提交的 CSV 里改 | 词表相对上游保持逐字节一致，每处改动的理由就紧挨着它，读起来一目了然 |
| 2026-09-03 | 中文叠加层随包发布，而不是留在 `tool/` 下 | 内容目录测试通过 `rootBundle` 读取它，并与实际发布的内容比对，从而能捕捉一次没有跑过 `--overlay-only` 的叠加层编辑 |
| 2026-09-03 | 参考页面偏好只存在设备本地，从不同步 | 手机和平板想要不同的列数，习惯是属于一台设备的 |
| 2026-09-03 | 路由器只构建一次，保存在根组件的状态里 | `GoRouter` 掌管导航历史；在主题变化时重建它会把用户送回初始标签页，会话中途被打断 |
| 2026-09-03 | AICore 通过应用自己的 Kotlin 方法通道访问，而不是一个 Flutter 插件 | 已发布的插件还是 0.x 版本，只包了 Prompt API，而且各自都应用了 Kotlin Gradle 插件——正是这条约束已经钉住了 `file_picker` 和 `speech_to_text` 的版本。两个客户端加五个方法，风险比多一个依赖小 |
| 2026-09-03 | 校对是与 Prompt 并列的第二个 GenAI 功能，有自己独立于开关的状态 | 它直接回答「我本该写什么」，并且支持日语；一台设备可能有其中一个模型而没有另一个，因此界面绝不能把「AI」当成一整块来对待 |
| 2026-09-03 | `minSdk` 从 Flutter 的 24 提到 26 | 这是 ML Kit GenAI 库唯一的要求；应用里没有其他东西需要它 |
| 2026-09-03 | `proguard-rules.pro` 保留全部 `com.google.mlkit.**` | R8 否则会把 ML Kit 压缩成一次运行期 NPE，而应用只会在 release 构建里把它报告成设备不受支持。只保留 `genai` 相关的包并不够——出问题的那一帧在 ML Kit 共享 SDK 的内部 |
| 2026-09-03 | 提示词以目录自己的语法说明为依据，问题提示则**按界面原样一字不差**地引用 | 一段与语法页对同一语法点的说法不一致的解释，或者回答了一个措辞不同的问题，都比什么都没有更糟 |
| 2026-09-03 | AI 开关直接把住方法通道本身，而不是把住结果 | 「关闭」必须意味着设备什么都没被问过，而不是一个答案被丢弃了；这是该服务测试里的第一条断言 |
| 2026-09-03 | 交叉链接是子串匹配，不是解析 | 真正的分词器是第三阶段的句子分析器；在那之前，一个错误的链接比没有链接代价更低，而这些筹片标注的是「这个例句用了它」，而不是标注为分析结果 |
| 2026-09-03 | Windows 与 macOS 工程随第二阶段落地，但 CI 仍只跑 Android | 发音与句子实验室需要一台真能运行应用的机器，而这台主机没有 Android 设备或模拟器；桌面 CI 任务、MSIX 与 Inno 产物留到第五阶段 |
| 2026-09-03 | Windows 窗口以 1000×720 打开，而不是兄弟应用的 400×860 | 在那个宽度下参考列表和设置已经是两列了，这正是桌面上值得看的布局；兄弟应用是手机形状的窗口，因为它们本来就是手机形状的应用 |
| 2026-09-03 | 设置仅在桌面上显示存储位置 | 在手机上那个路径指向一个用户既无法浏览也无法操作的沙盒；自定义存储路径本身在每个平台上都照常工作 |
| 2026-09-03 | 每个平台分支都住在 `shared/utils/platform_capabilities.dart` 里，读取 `defaultTargetPlatform` | 一个统一的家，与 `adaptive_layout.dart` 对宽度采用的规则相同；读取 `defaultTargetPlatform` 而不是 `dart:io` 的 `Platform`，正是让一个只跑 Android 的分支也能在 Windows 主机上测试的原因 |
| 2026-09-03 | `speech_to_text` 精确钉在 `7.4.0`，`flutter_tts` 钉在 `^4.2.5` | 两者都自行应用了 Kotlin Gradle 插件，这正是 `android.builtInKotlin=false` 所需要的——与钉住 `file_picker` 的约束相同。该插件的主分支已经放弃 KGP、改用 AGP 内置的 Kotlin，一个插入符号约束会在毫无预警的情况下弄坏 Android 构建 |
| 2026-09-03 | `TtsService` 一次只掌管一段朗读，以 `ValueNotifier` 对外发布 | 设备上只有一个语音；第二个朗读按钮如果表现得空闲、实则已排队，就是在对硬件实际的行为撒谎 |
| 2026-09-03 | 语音识别默认仅限离线，除非学习者打开一个开关；这个开关是除 WebDAV 同步外唯一一个会让任何东西离开设备的设置 | `EXTRA_PREFER_OFFLINE` 是失败而不是回退，而一次学习者能采取行动的失败，比一次悄悄的上传更诚实。开关的副标题说明了打开它意味着什么 |
| 2026-09-03 | 作答在打分前先通过一个内容目录索引改写 | Android 会在词条写着とうきょう时给出 東京 这样的答案；逐字比较会让一次完美的朗读得零分。一段无法解析的内容会原样抄过去，因此仍要付出编辑代价 |
| 2026-09-03 | 评分比较的是音拍，逐音拍的差异是主要输出 | 音拍是日语节奏计数的单位，也是听者判断的单位；单一一个数字无法说明该修哪一部分 |
| 2026-09-03 | 自录回放被推出 M2.2 之外 | 它需要与识别器同时使用麦克风，而在没有设备的主机上无法验证，还会再添两条原生 Windows 代码路径 |
| 2026-09-03 | 分词是一个求最短路径的代价词格，不是贪心最长匹配 | ここではなして 究竟切成 ここ/で/はなして 还是 ここ/では/なして，取决于后面接的是什么，一次从左到右的扫描无法知道。代价也让取舍变得明确、可测试，而不是把它们藏在循环顺序里 |
| 2026-09-03 | 不移植 TinySegmenter，与 M2.3 的设计相反 | 该设计原本只把它当作 −1 的取舍加分项来用。在 7,700 词条加功能词表的规模下，词格自己就能覆盖所有随包发布的例句，移植反而会为一项谁都不需要的加分引入一个要维护的模型 |
| 2026-09-03 | 语法匹配运行在 token 序列之上，而不新增 `match` schema | 〜は 需要的正是两端都落在 token 边界上；token 序列本身就提供了这一点，现有的字面形式已经可用，另一条路是重写 81 个语法点的 `match` 字段 |
| 2026-09-03 | 活用还原倒着跑，并对每个候选都拿词典核实一遍 | 正着来的话每个类别有十几种形式；倒着来，每个词干形状对每个类别都只是一次行变换，而放宽规则是安全的，因为 飲ん 会推出三个动词，词典只留下一个 |
| 2026-09-03 | 功能词表是带 `fw:` id 的内容，权威性高于词汇表 | は 作为主题助词出现的次数远多于作为 歯；一张分析器可以信任的表，正是让其余每个阶段成为可能的前提，而永不改变的 id 让一个 token 能够携带它 |
| 2026-09-03 | 繁体中文处处都是 `Locale('zh', 'TW')`：`app_zh_TW.arb`、存储的标签 `zh_TW`、内容键 `zh_TW` | 兄弟应用早已这样归档；现有的 `language_COUNTRY` 标签无需改动就能来回转换；一个读者只需学一次的字符串，在三处都用来命名它 |
| 2026-09-03 | 一个 `localeListResolutionCallback` 在 Flutter 自身的解析之前先归一化中文 | `basicLocaleListResolution` 只匹配语言和国家，因此 `zh-Hant-HK`、`zh-Hant-MO` 和 `zh-HK` 原本都会被给成简体中文。修正输入而不是替换算法，让其余每种语言都完全保持 Flutter 定义的样子 |

  单元和练习题的一段日语说明。它们全都通过了撰写门禁，却没有一份被日语或中文母语者读过。
  每个文件都在自己的 `source` 字段里注明了这一点。

  练习题抬高的不只是数量，更是风险。一条错误的释义是词典里错的一个词，学习者能自己查证；
  而一份模拟考卷上一个错误的答案键，会告诉某个人他答错了实际上答对的题，而备考程度估计
  正是建立在这些答案之上的。门禁在第四阶段被收紧了四次——每个句子都必须能解析、没有未知
  token，每个选项都必须互不相同，每道排序题都必须能重建出自己的句子——但它仍然无法判断
  一个句子是否自然，也无法判断某个干扰项是否不公平地接近正确答案。诚实的选项是找一位母语
  审校者，或者给学习者一个能看得见的渠道去举报一道有问题的题目。两者都还没有构建；在其中
  一个建成之前，标注就是答案的全部。
- **内容目录缺失的词。** 母、父、顔、東京、鞄 的汉字写法和 速い 不在词汇表里，因为生成词汇
  表所依据的 JLPT 词表本身不含它们；句子实验室对它们的容忍写在
  `test/fixtures/sentence/allowed_unknown.json` 里。例句批次和日语释义只能绕开它们写
  （一条关于 両親 或 表情 的释义很难完全避开 父 或 顔）。一个通过导入器合并进来的、手工
  维护的小型补充词表能补上这个缺口。
- **声调。** 只有在存在一份开放授权的声调词典时才值得做；识别器判断的是可辨识度，不是
  口音。
